## Rules a future session must not get wrong
- **★ NEVER GATE ON CLIP SHARE — use IN-MASK CHROMA.** Every compressive operator drives clip share to 0.000 while the surface can stay white and flat.
- **★ UF shape names do not transfer by name** — same-named variants compute different functions; per-shape thresholds are coverage-anchored.
- **★ ANY NEW FIELD-SIDE RENDER AXIS MUST ENTER THE FIELD-CACHE/REPLAY IDENTITY KEY** — GUARDED [code: renders.SPEC_MEMBERS · FIELD_IDENTITY · RECOLOR_MEMBERS; `field_job_name` refuses an unclassified member; shipped digests pinned in tests]. A variant parameterised through `mode_params` needs no new axis — it is already in both sets. **serialization is a RECORD KEY**: new fields `skip_serializing_if` their default or every cached picture renames; colormap-TAIL operators identify via provenance stamps.
- **★ ⚠ `renders.job_name` IS NOT A DURABLE IDENTITY.** It is a truncated sha256 of the WHOLE spec **and it digests `colormap_dir`, an absolute path into the checkout**, so it is MACHINE-DEPENDENT (demonstrated — repoint the dir and the job name moves); harmless as a render-cache file name, a trap for anything else, and `spec_of` is the ONLY derivation in the tree with a path in it. A moved or re-cloned checkout misses the entire render cache. ⚠ **Never pin its digest in a test** — doing so left CI red on both runners for three days, invisible locally. ⚠ **It does NOT carry the mode catalog** (measured ckpt 90, correcting two eras of this line): it digests that row's OWN coloring, so adding a catalog entry renames nothing and only changing an existing mode's own coloring renames that mode's cached views. The catalog pin stays declined and is now unnecessary.
- **★ `autolevel` IS A PIXEL-DECIDING INPUT OUTSIDE EVERY DIGEST THIS PROJECT HAS.** It re-renders through a colormap built from the band file, so a picture is a function of `levels_band.json`'s sha too and **is not a lookup into the map that named it** — any recipe key must carry that sha. ⚠ Supersampling and JPEG average colour AFTER the lookup, so a stored picture can hold colours no ramp position holds; exact only at ss1/PNG. **★ THE OPERATOR'S INPUT IS THEREFORE THE ENCODED PICTURE, AND THE ENGINE ROUTE IS CLOSED PERMANENTLY (measured):** `resample::downsample` hands the encoder an sRGB8 buffer and the encoder is lossy, so the engine never holds the pixels `measure` reads — the same field to `.jpg` and `.png` changes the levelled stop list on most firing candidates. Reporting them from Rust would draw a different picture under the SAME recipe key. `autolevel.applies_to` is `field` and `composite` ONLY.
- **★ THE FIELD IS DUMPABLE AND A RECOLOUR IS BYTE-IDENTICAL TO A RENDER** [code: `colorize.field_of` · `colorize.recolored`; pinned digests]. Three consequences the mechanism forces. **The dump amortises per (location, MODE), so cutting the mode roster is a bigger lever than cutting palettes.** **A field dumped BY MODE NAME carries the CATALOGUE's curve** — one mode shipped `log` where curation renders `linear` and computed silently wrong until pinned. And **composites and direct traps cannot dump** (no single scalar field; dumping a composite's two layers separately measured DEARER than rendering it, so only a two-layer dump would pay) — a direct-trap unit is ONE render, not two.
- **★ THE ENGINE BUILD IS THE FIFTH PIN**, beside colormap, cyclicity, node width and cap policy: an engine-output fingerprint recorded by `identity.enforce`; `drawn_by.jsonl` stamps every node view AND gate render; **an unstamped or mismatched view is STALE = re-rendered, never scored** [code: engine_fingerprint.py · intake.gate_render · tests/test_engine_fingerprint.py]. The stamp is BESIDE the picture, not in its name — a build in the digest would orphan every `score_view`. Scores overlay `score_amendments.jsonl` via `intake.read_scores` — **never open the sidecar directly**; the amendment is regenerable at a cost of hours, with no durable copy. ⚠ **NO CANDIDATE RENDER CARRIES AN ENGINE STAMP** — the fingerprint stamps VIEW DIRECTORIES only, and pre-stamp candidate material is ACCEPTED as unknown-engine (Matt): the pin catches future drift, it does not certify history. `neutral_embeddings` carries no engine pin.
- **★ THE HOME VIEW IS A RUST CONSTANT** — `Family::home_view()` → `Extent::frame()`; height is always width × 9/16; **Python holds NO copy** and the one door is `engine.home_view(family)` (`discovery.boundary.home_box` shrinks it by `HOME_SHARE`; the website's `permalink.test.mjs` keeps a text copy; `engine.screen` is the gate battery, not a window).
- **★ `Coloring::Modulate` TAKES ANY LAYER** — `position = frac(rank(base) + shift · normalize(texture))`; **the base is spent BY RANK, always**, part of the definition and enforced by `Coloring::agrees_with`, which refuses a recipe asking any other transfer. `itinerary` is the one shipped instance (texture `FieldSpec::Itinerary`, the orbit's angular address written as base-4 digits of one fraction; `start` = `z1` on a dynamical plane, `z0` on a parameter one; catalog base `smooth_base()`). **Where the base is detailed its rank sweeps fast and the shift is a minor recolour; where the base is FLAT the shift is the only variation — so the texture fills the BORING regions, which no field-space blend does.** The only engine-level constraints on modulating some other mode are `field.conflicts_with` (a field cannot modulate itself) and the rank rule. Python-side it is kind `modulate`: `dumpable_field()` is `None`, `colorize.shareable` False, never in the depth roster.
- Diagnostic heuristics worth keeping in reach: **production mirrors non-cyclic colormaps and a field piling up at one end loses nearly everything under a mirrored map** — treat mirroring as the prime suspect when a trap-like mode underperforms; figure/rank work uses plain sweeps. **GENERICITY, NOT MULTIPLICITY, IS THE PERF TRAP** and the FAMILY spread dwarfs the mode spread — **never re-quote any perf figure from before ckpt 73**; live numbers and the regression guard are website `explorer/README.md §Measured` + `explorer/bench/`. **`data/palettes` never stores the engine's baked table size** — anything comparing maps must SAMPLE positions through the bake's Oklab interpolation, unfolded (→ `palettes/README.md`).
