## Rules a future session must not get wrong
- **★ NEVER GATE ON CLIP SHARE — use IN-MASK CHROMA.** Every compressive operator drives clip share to 0.000 while the surface can stay white and flat. A maker-archive method rule: nothing in `src/` gates on clip share.
- **★ UF shape names do not transfer by name** — same-named variants compute different functions; per-shape thresholds are coverage-anchored.
- **★ ANY NEW FIELD-SIDE RENDER AXIS MUST ENTER THE FIELD-CACHE/REPLAY IDENTITY KEY** [ENFORCED: `test_renders.py:147,206,214,220` plants a fake member and asserts the raise at `renders.py:178`; shipped field digests pinned at `test_curation_colorize.py:244,252,281`]. A variant parameterised through `mode_params` needs no new axis — it is already in both sets. **Serialization is a RECORD KEY**: new fields `skip_serializing_if` their default or every cached picture renames; colormap-TAIL operators identify via provenance stamps.
- **★ ⚠ `renders.job_name` IS NOT A DURABLE IDENTITY.** A truncated sha256 of the WHOLE spec that digests `colormap_dir`, an absolute path into the checkout, so it is MACHINE-DEPENDENT — harmless as a render-cache file name, a trap for anything else. `spec_of` is the ONLY derivation in the tree with a path in it [ENFORCED for the recipe key: `renders.spec_of:322`; `test_candidate_ledger.py:105` drops both paths]. A moved or re-cloned checkout misses the entire render cache. ⚠ **Never pin its digest in a test** — a discipline, unenforced: doing so left CI red on both runners for three days, invisible locally. The one digest pin in the tree bites only because its fixture neutralises `colormap_dir` first (`test_curation_colorize.py:210`). ⚠ **It does NOT carry the mode catalog** — `spec_of` reads that row's OWN coloring, so adding a catalog entry renames nothing and only changing an existing mode's own coloring renames that mode's cached views.
- **★ `autolevel` IS A PIXEL-DECIDING INPUT OUTSIDE EVERY DIGEST THIS PROJECT HAS** [ENFORCED: `autolevel.applies_to:156` returns `field` or `composite` only; the band sha sits in `recipes.KEYED`; `test_candidate_ledger.py:83` shows one engine spec, two bands, two recipe keys and one `job_name`]. A picture is a function of `levels_band.json`'s sha and **is not a lookup into the map that named it** — any recipe key must carry that sha. ⚠ Supersampling and JPEG average colour AFTER the lookup, so a stored picture can hold colours no ramp position holds; exact only at ss1/PNG. **★ THE OPERATOR'S INPUT IS THEREFORE THE ENCODED PICTURE, AND THE ENGINE ROUTE IS CLOSED PERMANENTLY (measured):** `resample::downsample` hands the encoder an sRGB8 buffer and the encoder is lossy, so the engine never holds the pixels `measure` reads — the same field to `.jpg` and `.png` changes the levelled stop list on most firing candidates. Reporting them from Rust would draw a different picture under the SAME recipe key.
- **★ THE FIELD IS DUMPABLE AND A RECOLOUR IS BYTE-IDENTICAL TO A RENDER** [ENFORCED: `test_curation_colorize.py:520`, slow; the composite/direct-trap refusal at `mode.rs:426` covering all eleven non-field modes, `colorize.shareable`, `test_curation_colorize.py:506`]. **The dump amortises per (location, MODE), so cutting the mode roster is a bigger lever than cutting palettes.** ⚠ **A field dumped BY MODE NAME carries the CATALOGUE's curve** — one mode shipped `log` where curation renders `linear` and computed silently wrong until pinned; the failure is silent wrongness, not an error. And **composites and direct traps cannot dump** — dumping a composite's two layers separately measured DEARER than rendering it, so only a two-layer dump would pay, and a direct-trap unit is ONE render, not two.
- **★ THE ENGINE BUILD IS THE FIFTH PIN**, beside colormap, cyclicity, node width and cap policy: an engine-output fingerprint recorded by `identity.enforce`, with `drawn_by.jsonl` stamping every node view and gate render; **an unstamped or mismatched view is STALE = re-rendered, never scored** [ENFORCED: `test_engine_fingerprint.py:109-131` fast, `:151,177` slow. The gate is `curation/intake.py:236`]. The stamp is BESIDE the picture, not in its name — a build in the digest would orphan every `score_view`. Scores overlay `score_amendments.jsonl` via `intake.read_scores` [ENFORCED for the six reader call sites: `test_engine_fingerprint.py:348-403`]; **never open the sidecar directly** is a discipline and unenforced. The amendment is regenerable at a cost of hours, with no durable copy. ⚠ **NO CANDIDATE RENDER CARRIES AN ENGINE STAMP** — verified: every `stamps(...)` call site is `discovery/scoring.py`, `models/location_view.py`, `curation/amend.py` or `curation/intake.py`. Pre-stamp candidate material is ACCEPTED as unknown-engine (Matt): the pin catches future drift, it does not certify history. `neutral_embeddings` carries no engine pin.
- **★ THE HOME VIEW IS A RUST CONSTANT** — `Family::home_view()` → `Extent::frame()`, height always width × 9/16; **Python holds NO copy** and the one door is `engine.home_view(family)` [ENFORCED both halves: `test_home_views.py:66,78,90,108`; the 9/16 at `screen.rs:292`, `family.rs:745,778`]. `discovery.boundary.home_box` shrinks it by `HOME_SHARE`; the website's `permalink.test.mjs` keeps a text copy; `engine.screen` is the gate battery, not a window. `Family::home_view()` returns `Option<HomeView>` and julia is a declared exception carrying `derived: false`, not a row the rule lands on.
- **★ `Coloring::Modulate` TAKES ANY LAYER** — `position = frac(rank(base) + shift · normalize(texture))`; **the base is spent BY RANK, always**, part of the definition [ENFORCED: `coloring.rs:645,1944-1958` and `field.rs:1539`; `mode.rs:441` asserts exactly one shipped modulate; Python-side kind `modulate` at `colorize.shareable:278` and `depth.field_modes:212` — `dumpable_field()` is `None`, never in the depth roster]. `itinerary` is the one shipped instance (texture `FieldSpec::Itinerary`, the orbit's angular address written as base-4 digits of one fraction; `start` = `z1` on a dynamical plane, `z0` on a parameter one; catalog base `smooth_base()`). **Where the base is detailed its rank sweeps fast and the shift is a minor recolour; where the base is FLAT the shift is the only variation — so the texture fills the BORING regions, which no field-space blend does.** The only engine-level constraints on modulating some other mode are `field.conflicts_with` and the rank rule.
- Diagnostic heuristics worth keeping in reach: **production mirrors non-cyclic colormaps and a field piling up at one end loses nearly everything under a mirrored map** — treat mirroring as the prime suspect when a trap-like mode underperforms; figure/rank work uses plain sweeps. **GENERICITY, NOT MULTIPLICITY, IS THE PERF TRAP** and the FAMILY spread dwarfs the mode spread — **never re-quote any perf figure from before ckpt 73**; live numbers and the regression guard are website `explorer/README.md §Measured` + `explorer/bench/`. **`data/palettes` never stores the engine's baked table size** — anything comparing maps must SAMPLE positions through the bake's Oklab interpolation, unfolded (→ `palettes/README.md`).
