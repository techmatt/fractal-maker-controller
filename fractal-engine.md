## Rules a future session must not get wrong
- **★ NEVER GATE ON CLIP SHARE — use IN-MASK CHROMA.** Every compressive operator drives clip share to 0.000 while the surface can stay white and flat. A maker-archive method rule: nothing in `src/` gates on clip share.
- **★ UF shape names do not transfer by name** — same-named variants compute different functions; per-shape thresholds are coverage-anchored.
- **★ ANY NEW FIELD-SIDE RENDER AXIS MUST ENTER THE FIELD-CACHE/REPLAY IDENTITY KEY** [ENFORCED: `test_renders.py:147,206,214,220` plants a fake member and asserts the raise at `renders.py:212`; shipped field digests pinned at `test_curation_colorize.py:244,252,281`]. A variant parameterised through `mode_params` needs no new axis — it is already in both sets. **Serialization is a RECORD KEY**: new fields `skip_serializing_if` their default or every cached picture renames; colormap-TAIL operators identify via provenance stamps.
- **★ ⚠ `renders.job_name` IS NOT A DURABLE IDENTITY.** A truncated sha256 of the WHOLE spec that digests `colormap_dir`, an absolute path into the checkout, so it is MACHINE-DEPENDENT — harmless as a render-cache file name, a trap for anything else. `spec_of` is the ONLY derivation in the tree with a path in it [ENFORCED for the recipe key: `renders.spec_of:355`; `test_candidate_ledger.py:108` drops both paths]. A moved or re-cloned checkout misses the entire render cache. ⚠ **Never pin its digest in a test** — a discipline, unenforced: doing so left CI red on both runners for three days, invisible locally. The one digest pin in the tree bites only because its fixture neutralises `colormap_dir` first (`test_curation_colorize.py:210`). ⚠ **It does NOT carry the mode catalog** — `spec_of` reads that row's OWN coloring, so adding a catalog entry renames nothing and only changing an existing mode's own coloring renames that mode's cached views.
- **★ `autolevel` IS A PIXEL-DECIDING INPUT OUTSIDE EVERY DIGEST THIS PROJECT HAS** [ENFORCED: `autolevel.applies_to:156` returns `field` or `composite` only; the band sha sits in `recipes.KEYED`; `test_candidate_ledger.py:85` shows one engine spec, two bands, two recipe keys and one `job_name`]. A picture is a function of `levels_band.json`'s sha and **is not a lookup into the map that named it** — any recipe key must carry that sha. ⚠ Supersampling and JPEG average colour AFTER the lookup, so a stored picture can hold colours no ramp position holds; exact only at ss1/PNG. **★ A LEDGER ROW CANNOT REPLAY ITS LEVELLED COLORMAP** — `recipes.stamp_of` deliberately drops the derived curve, so `<key>.leveled/` is RE-RENDERABLE (one candidate render) and not replayable; a `manufacture` row carries the whole curve and can be replayed. `delete_pictures` takes the sibling `<key>.leveled` with the JPEG, so the pile is bounded by the ledger. **★ THE OPERATOR'S INPUT IS THEREFORE THE ENCODED PICTURE, AND THE ENGINE ROUTE IS CLOSED PERMANENTLY (measured):** `resample::downsample` hands the encoder an sRGB8 buffer and the encoder is lossy, so the engine never holds the pixels `measure` reads — the same field to `.jpg` and `.png` changes the levelled stop list on most firing candidates. Reporting them from Rust would draw a different picture under the SAME recipe key.
- **★ THE FIELD IS DUMPABLE AND A RECOLOUR IS BYTE-IDENTICAL TO A RENDER** [ENFORCED: `test_curation_colorize.py:545`, slow; the composite/direct-trap refusal in `mode.rs`, `colorize.shareable`, `test_curation_colorize.py:531`]. **The dump amortises per (location, MODE), so cutting the mode roster is a bigger lever than cutting palettes.** ⚠ **A field dumped BY MODE NAME carries the CATALOGUE's curve** — one mode shipped `log` where curation renders `linear` and computed silently wrong until pinned; the failure is silent wrongness, not an error. And **composites and direct traps cannot dump** — dumping a composite's two layers separately measured DEARER than rendering it, so only a two-layer dump would pay, and a direct-trap unit is ONE render, not two.
- **★ THE ENGINE BUILD IS THE FIFTH PIN**, beside colormap, cyclicity, node width and cap policy: an engine-output fingerprint recorded by `identity.enforce`, with `drawn_by.jsonl` stamping every node view and gate render; **an unstamped or mismatched view is STALE = re-rendered, never scored** [ENFORCED: `test_engine_fingerprint.py:109-131` fast, `:151,177` slow. The gate is `curation/intake.py:265`]. The stamp is BESIDE the picture, not in its name — a build in the digest would orphan every `score_view`. Scores overlay `score_amendments.jsonl` via `intake.read_scores` [ENFORCED for the six reader call sites: `test_engine_fingerprint.py:348-403`]; **never open the sidecar directly** is a discipline and unenforced. The amendment is regenerable at a cost of hours, with no durable copy. ⚠ **NO CANDIDATE RENDER CARRIES AN ENGINE STAMP** — pre-stamp candidate material is ACCEPTED as unknown-engine (Matt): the pin catches future drift, it does not certify history. `neutral_embeddings` carries no engine pin. ⚠ The fingerprint probes SIX fixed rows of the production roster — a change confined to an unprobed mode moves nothing it reads and a NEW mode is invisible outright (docstring says so; `mode_policy.check` is what a new mode trips).
- **★ THE HOME VIEW IS A RUST CONSTANT** — `Family::home_view()` → `Extent::frame()`, height always width × 9/16; **Python holds NO copy** and the one door is `engine.home_view(family)` [ENFORCED both halves: `test_home_views.py:66,77,90,110`; the 9/16 at `screen.rs:292`, `family.rs:745,778`]. `discovery.boundary.home_box` shrinks it by `HOME_SHARE`; `engine.screen` is the gate battery, not a window. The julia exception (`Option<HomeView>`, `derived: false`) is CRATE-INTERNAL — the wasm surface exports a plain whole-plane home like every family, and **the website's `permalink.test.mjs` HOMES text copy is now PINNED to the wasm** [ENFORCED: the website node suite compares all nine families as text], closing the old silent-drift path.
- **★ TWO SHIPPED MODULATES; the mechanics live in `engine/README.md §Modulate`** (absorbed ckpt 94: the definition — `position = frac(rank(base) + shift·normalize(texture))`, **the base spent BY RANK, always** — catalog constants, `conflicts_with` name-equality, base narrowed to f32, the degeneracy computation site, and that a full written-out coloring renders from spec so contact sheets are free). `itinerary` is production (weight 2, Matt); `tail_itinerary` is weight 0 by ruling — not gallery-worthy, the address frequency too abrupt (→ settled_rulings). Where the base is detailed the shift is a minor recolour; **where the base is FLAT the shift is the only variation — the texture fills the BORING regions, which no field-space blend does.** Catalogue counts: 8 field + 6 composite + 2 modulate + 4 direct = 20, `de` niche, so 19 production [ENFORCED: the split test at `mode.rs:480`; `mode.rs:495` asserts two shipped modulates].
- **★ A FLAT TEXTURE IS SMOOTH-WITH-RANK (ruling, ckpt 94).** The engine reports `texture_flat` per render — verified bit-for-bit at production geometry against `smooth` + `transfer:{"kind":"rank"}` [ENFORCED: the engine guard produces the degenerate output as bits; `tests/test_texture_flat.py` covers the report, the row, the key and every reader] — and the ONE spelling of the routing is `mode_policy.routed_mode` / `hunt.kind_of(mode, texture_flat)`, sound over the whole catalog (every composite's and modulate's base is `smooth_base()`, engine-asserted). Rows that predate the flag: **`data/coloring/texture_flat.jsonl` is a TRACKED register** (the label corpus depends on it), keyed on the engine spec LESS the recolour half — and **GEOMETRY IS IN THE KEY**: a shipping grid may resolve a texture the candidate grid flattened, so the flag is per (location, mode, geometry), never per recipe. ⚠ The f32 field dump is NOT ground truth for the texture (base-4 spends the mantissa after 11 symbols, `iterate.rs:203`); truth is the engine's span test ≡ the shift-pair render, verified agreeing by both methods over the full record.
- Diagnostic heuristics worth keeping in reach: **production mirrors non-cyclic colormaps and a field piling up at one end loses nearly everything under a mirrored map** — treat mirroring as the prime suspect when a trap-like mode underperforms; figure/rank work uses plain sweeps. **GENERICITY, NOT MULTIPLICITY, IS THE PERF TRAP** and the FAMILY spread dwarfs the mode spread — live numbers are website `explorer/README.md §Measured`; `explorer/bench/` is a RE-MEASURE HARNESS, not a guard (no assertions, nothing runs it; a threshold is deliberately unwired — a reading is one machine on one day). Old perf figures → settled_rulings. **`data/palettes` never stores the engine's baked table size** — anything comparing maps must SAMPLE positions through the bake's Oklab interpolation, unfolded (→ `palettes/README.md`).
