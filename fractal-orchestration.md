# fractal-orchestration — production loop & run safety

Changes when: orchestrator work. Owns how runs launch, isolate, and stop. **Run-safety mechanics (detach, liveness, atomic writes, resume, shakedown, caps) → `docs/design/verification_practice.md` §11 — cite in prompts, never restate.**

**Production loop:** `tools/atlas/steered_frontier.py` (batch loop, active-time budget, per-batch state, sentinel at batch boundary); **allocator = `--pop-quota`** (`--scheduler` retired; mutually exclusive; targets ∝ `release_mix` — fractal-discovery owns the rule) + `--freshness-prior` (breadth ONLY) → run-scoped ledger → dive leg (`--dive`, prior OFF) → stage-1 intake → colorize/gate/pool/select → RELEASE. GPU-EXCLUSIVE phasing (one 8 GB card). `production_seeder.py` is the standing discovery flow.

- **Durable principles:** cap = accumulated active time; sentinel-stop at the state-consistent boundary; reconciliation per unit (`found == written + dropped_*` else loud exit); **admissions = the ledger's `distinct=True` rows, never its line count** (the ledger keeps its non-distinct near-dups; `harvest_log.admitted` matches `distinct` exactly); TWO dedup layers (any rate on raw decodes ~2× optimistic); operational failure ≠ leak. An ACTIVE cap alone does not bound wall — pair with `--wall-budget` (clock starts at LOOP ENTRY; never covers the pre-loop draw; refused in dive mode [code: `check_wall_budget_supported`]). Per-check telemetry durable (`harvest_log.jsonl` beside the ledger — the τ_h cost curve regenerates).
- **The pre-loop root draw runs OUTSIDE both caps — bounded via `--root-draw-budget`** [code]; deadline arithmetic subtracts the draw bound explicitly. Cost is set by CONTENTION, not family count — **stable at ~8.2 min of a 15-min bound two runs running (26: 8.07, 27: 8.21), so the bound does NOT need to be generous**; ⚠ the check is BETWEEN draws, so a tight budget overshoots by up to one draw (+51% observed at a 180 s bound). **Size at `wall_over_active` 1.15** — realized 1.02 on both production runs (26: 1.01); **★ the margin covers the leg's TEARDOWN, not its loop — name it that way**, and **★ apply it PER-LEG, not to the whole-run cap** [run 25: 8h/1.15 for the frontier alone leaves no room for the other legs — the multi-leg pattern].
- **Per-partition refill** [code: `steered_frontier.refill_starved`]: low-water fires `draw_roots` for starved partitions; cooldown + `--root-refill-share` (the ONLY bound on refill spend). **The pre-loop draw dominates any short frontier smoke** — budget wall for it; `production_seeder --smoke` has BUFFERED stdout — read `<sink>/outcome_ledger.jsonl` for progress.
- **★ A scheduler run refuses to start unseeded** — `require_library_seed()` raises; `summary.json` carries `library_seed` + a screaming `UNSEEDED_RUN` key. Seed at registered BULK (ordered REGISTRY; resolvers REFUSE scratch paths [code]); pop-quota never reads it.
- **★ SINK ISOLATION (`tools/atlas/discovery_sinks.py`) — one decision point.** `--smoke`/`--time-only` with no explicit `--discovery-dir` redirects the WHOLE discovery store to ephemeral scratch. Smoke rows are current-decode ⇒ admissible — contamination the decode firewall cannot catch. **A real experimental run is NOT a smoke — give it its own run directory.** `steered_frontier` takes an explicit `--run-dir` with no default, so it cannot fall through to the production store.
- **★ CONCURRENCY — 7 IS THE NUMBER.** (a) ONE `fractal-generator.exe` → 7 threads; (b) 4+ in parallel → think. **BelowNormal ALWAYS.** Committed defaults: `corpus_common.DEFAULT_ENGINE_THREADS` + `default_engine_env()` / `default_creationflags()` — **call the helpers, never restate the number.** `run_render_one` defaults `low_priority=True` (explorer = the one opt-out). Machine: 12 logical cores, RTX 2060 SUPER 8 GB.
- **The suite can't see the loud-late surface** → before trusting a structural change: `production_seeder --smoke` + a frontier smoke + the sink-isolated emission smoke (legacy-path minis retired 2026-08-10 with their orchestrators; their loop coverage lives in the frontier leg); the detach rules apply to smoke legs too; sink isolation means none can reach production data. ⚠ **The gate-draw shakedown lane went with `deploy_tail`'s driver (`d73a6c6`) — `--ephemeral` on `build_emission_diversity_v1` is a DIFFERENT, LIVE flag**, the emission sink-isolation lane the emission smoke runs on. **Reject autopsy — standing habit:** fate-stratified sheets at deploy fidelity; every readout emits numbers AND a visual sample of admissions + rejects.
- **Dive legs:** plan arms apportionment-interleaved so truncation keeps both arms [code: `interleave_dive_arms`]; the dive path writes `run_config.json`. **Run-record telemetry is SEGMENTED** [code: `tools/run_record.py`]: heavy jsonl streams rotate into gzipped segments + bounded plain tail; readers via `run_record.iter_rows`; assert the registry's LOGICAL stream (`run_record.exists()`), never the physical filename. **★ On CLEAN CLOSE every per-batch stream rotates to `<stem>.NNN.jsonl.gz` and the live file is REMOVED** — a post-run reader reads live + every rotation; a try/except open of the live path finds nothing SILENTLY.
- **★ `steered_frontier` TEARS DOWN ITS OWN SCRATCH ON CLEAN CLOSE** [code; `--retain-scratch` opts out; an INTERRUPTED run never tears down] — generalized in `storage_classes.md` §5.6: a per-run bulk producer owns its teardown. **Run-scratch draw is a RANGE, mix-dependent — 20.7–29.8 GB/h observed (runs 26/27); this SUPERSEDES the ~18 GB/engine-hour point figure.** Freed ONLY on clean close, so the trough hangs off the teardown; run 27 projected ~58 GB free against the guard's 25 GB STOP. ⚠ **RUN-26 ERRATUM — its report's 147 GB was the POST-TEARDOWN reading; the trough was 89.7 GB, so run 26 drew 74 GB, not 17, and its projection was ACCURATE, not 5× conservative.** Run 27 carried no pruning ladder on the strength of that misread number. The bulk-store size watch is BUILT (fractal-storage owns it); an in-run pruner inside `steered_frontier` remains the named durable follow-on if the watch ever fires.
- **★★ STANDING STAGE PROFILING (`25ab4e9`).** `stage_times.jsonl`, per unit of work — one writer (`tools/stage_times.py`), one schema (`stage`/`unit`/`dur_s`/`t_end`/`seq` + free-form `meta`), EIGHT record sites (`root_draw`/`root_refill`/`frontier_batch`/`dive` in the frontier; `intake`/`colorize`/`select`/`release_render` in emission), plus session totals folded into each `summary.json`. **Nothing reads it back in-run and no cutoff consults it — zero behaviour change is STRUCTURAL, not a claim.** Reader `tools/run_profile.py` ranks top-N **by ratio to their own stage's median** (>3× flagged; sorting by SECONDS returns the release renders every time and buries the colorize attempt that took 30× its peers), gives a stage under 5 units no flags, and cross-checks per-unit totals against the run's own aggregates — **that pair disagreeing is a batch that ran and was never charged, which nothing else in the record would say.** Discovery half COMMITTED, emission half still scratch (fractal-storage). Run-26 baseline BACKFILLED off its console logs (`source=log_backfill`, 1 s quantization, `t_end` OMITTED rather than invented — so run 26 has no span at all). **Tail concentration is a TUTORIAL-ERA WATCH: 54.5% of the leg in the batches over 3× median, improving from run 26's 61.8% — twice the batches at half the per-batch cost, and the flatter tail is the direction to keep.**
- **★ BUDGET ARITHMETIC — the corrected numbers** (run-27 launch §corrections): the emission leg is **≈90 min at `--release-n 12`** — intake 56.6% / release renders 34.3% / colorize 9.1%. The shakedown's 94.9%-intake figure was a **`--release-n 2` smoke artifact**, and its "~29 min uncontended" intake understated the leg ~1.9× because it extrapolated a FILE RATE rather than measuring a leg — **budget a leg off an observed leg, never off a rate.** Intake is independent of `--release-n`; the release renders are emphatically not. **A dive leg's FIRST dive is unbounded by `--budget`** (`est_batch_s` is 0 until one completes, so nothing can pre-check it) — real, and it cost 1.07 min when reserved for.
- **⚠ `--seed` MUST NOT COLLIDE WITH A PRIOR SAME-DATE RUN** — a date seed replays the root draw against a store already holding that run's admissions. Run 27 launched on run 26's calendar date and used `--seed 20260813` for exactly this reason.
- **Cross-run saturation memory — LIVE.** The ledgers ARE the cross-run memory, identity-aware, breadth-leg within-partition only; mechanism/constants → `discovery_pipeline.md` §5. **Two production exercises in range — different estimands (leave-one-run-out vs one run's stream); quote §5.2 as a bound, not a prediction; run reads live in the run records.**
