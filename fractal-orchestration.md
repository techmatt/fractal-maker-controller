# fractal-orchestration — production loop & run safety

Changes when: orchestrator work. Owns how runs launch, isolate, and stop.

**Production loop:** `tools/atlas/steered_frontier.py` (batch loop, active-time budget, per-batch state, sentinel at batch boundary); **production allocator = `--pop-quota` (Matt, 2026-08-04; `--scheduler` retired as policy → `retired.md`; the flags are mutually exclusive; targets ∝ `release_mix` ratios — fractal-discovery owns the rule)** + `--freshness-prior` (breadth ONLY) → run-scoped ledger → dive leg (`--dive`, scheduler-ordered, prior OFF) → stage-1 intake (`tools/emission/`) → colorize/gate/pool/select → RELEASE. GPU-EXCLUSIVE phasing (one 8 GB card). `production_seeder.py` (26 importers) is the standing discovery flow; `present` has no live invoker.

- **Durable principles:** cap = accumulated active time; sentinel-stop at the state-consistent boundary [live-proven 2026-08-04]; reconciliation per unit (`found == written + dropped_*` else loud exit); TWO dedup layers (any rate on raw decodes ~2× optimistic); operational failure ≠ leak. **Launch long runs DETACHED** — the reaper kills waited/shelled tasks, never detached processes. An ACTIVE cap alone does not bound wall (`draw_roots` sits outside it) — pair with `--wall-budget`, whose clock starts at LOOP ENTRY: it can NEVER cover the pre-loop draw (budget wall for that separately); refused in dive mode [code: `steered_frontier.check_wall_budget_supported`]. A STOP sentinel at a batch boundary is the clean external cut.
- **Per-check telemetry is DURABLE** — `harvest_log.jsonl` committed beside the ledger, so every run regenerates the τ_h cost curve automatically. ⚠ `campaign1`'s 37,853 rows are pre-geometry, not re-scoreable, permanently (HARVEST arm only; the walk-outcome ledger has no pre-geometry rows — two populations).
- **The pre-loop root draw runs OUTSIDE both caps — bounded via `--root-draw-budget`** [code; default byte-identical; `wall_elapsed_s` counts the BATCH LOOP only, so deadline arithmetic subtracts the draw bound explicitly]. Cost is set by CONTENTION, not family count (8–9 min quiet). **Size at `wall_over_active` 1.15 as margin** — both 2026-08-07 production runs realized 1.01–1.02 with the draw bounded; 1.05-when-replenishment-never-fires stays a defect signal (fractal-discovery).
- **Per-partition refill (2026-08-04)** [code: `steered_frontier.refill_starved`]: per-partition low-water (default =B; at B=32 × 10 partitions an implied 320-node floor — expect early, frequent refills) fires `draw_roots` for starved partitions; `--root-refill-cooldown 10` batches + `--root-refill-share 0.25` of loop wall — the share cap is the ONLY bound on refill spend. A root draw ≈ **1.5 min/family**. **The pre-loop root draw dominates any short frontier smoke** (8.4 min against a 2-min loop) — budget wall for it, not `--budget`. `production_seeder --smoke` runs **~18 min** with BUFFERED stdout — read `<sink>/outcome_ledger.jsonl` for progress.
- **★ A scheduler run refuses to start unseeded** — `require_library_seed()` raises (`--allow-unseeded`, scoped to `--scheduler`), preflight before any write; `summary.json` carries `library_seed` + a screaming `UNSEEDED_RUN` key; a never-called seeder records `never_attempted`, not an absent key.
  - **Seed at registered BULK (2026-08-04):** 168 looks / 9 partitions, regenerates bit-identically ~13 min; seed-source resolution is an ordered REGISTRY and resolvers REFUSE scratch paths [code]. Pop-quota never reads it (demand = labels); the flip-unreconstructability caveat still applies to any seed-reading mode.
- **★ SINK ISOLATION (`tools/atlas/discovery_sinks.py`) — one decision point.** `--smoke`/`--time-only` with no explicit `--discovery-dir` redirects the WHOLE discovery store to ephemeral scratch. Smoke rows are current-decode ⇒ admissible — contamination the decode firewall cannot catch. **A real experimental run is NOT a smoke — give it its own run directory.** `steered_frontier` has no smoke flag and takes an explicit `--run-dir` with no default, so it cannot fall through to the production store.
- **★ CONCURRENCY — 7 IS THE NUMBER.** (a) ONE `fractal-generator.exe` → 7 threads; (b) 4+ in parallel → think, no standing number. **BelowNormal ALWAYS.** Committed defaults: `corpus_common.DEFAULT_ENGINE_THREADS` + `default_engine_env()` / `default_creationflags()` — **call the helpers, never restate the number.** `render_core.run_render_one` defaults `low_priority=True` (explorer = the one opt-out). Machine: 12 logical cores, RTX 2060 SUPER 8 GB.
- **The suite can't see the loud-late surface** → before trusting a structural change: both legacy orchestrators `--mini` + `production_seeder --smoke` + a frontier smoke + the sink-isolated emission smoke (fractal-emission owns it); sink isolation means none can reach production data. `deploy_tail` sites are NOT on that surface (fractal-emission).
- **Reject autopsy — standing habit:** fate-stratified sheets at deploy fidelity; every readout emits numbers AND a visual sample of admissions + rejects.
- **Dive legs (2026-08-05):** plan arms apportionment-interleaved so any truncation keeps both arms [code: `steered_frontier.interleave_dive_arms`, injection-proven]; the dive path writes `run_config.json`. **Run-record telemetry is SEGMENTED (2026-08-07)** [code: `tools/run_record.py`]: the 5 heavy jsonl streams rotate at size into gzipped segments + a bounded plain tail (compressed at run end, crash-safe by rename); readers via `run_record.iter_rows`; legacy dirs unchanged. Measured 4.2× tree-bytes overall (9.5–10.5× on the streams); an 8h run projects ~17 MB worst-case vs the 20 MB TREE-BYTES rule (fractal-storage owns the framing). **★ The un-segmented pair — `outcome_ledger.jsonl` (66 readers, some `rglob`: segmenting it silently shortens their population) + `outcome_feats.npz` — is now 55% of the record and is what a longer run crosses the rule on; needs its own pass.** Guard lesson: assert the registry's LOGICAL stream (`run_record.exists()`), never the physical filename — a finalized run has no plain file.
