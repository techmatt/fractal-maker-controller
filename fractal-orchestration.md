# fractal-orchestration — production loop & run safety

Changes when: orchestrator work. Owns how runs launch, isolate, and stop. **Run-safety mechanics (detach, liveness, atomic writes, resume, shakedown, caps) → `docs/design/verification_practice.md` §11 — cite in prompts, never restate.**

**Production loop:** `tools/atlas/steered_frontier.py` (batch loop, active-time budget, per-batch state, sentinel at batch boundary); **allocator = `--pop-quota`** (`--scheduler` retired; mutually exclusive; targets ∝ `release_mix` — fractal-discovery owns the rule) + `--freshness-prior` (breadth ONLY) → run-scoped ledger → dive leg (`--dive`, prior OFF) → stage-1 intake → colorize/gate/pool/select → RELEASE. GPU-EXCLUSIVE phasing (one 8 GB card). `production_seeder.py` is the standing discovery flow.

- **Durable principles:** cap = accumulated active time; sentinel-stop at the state-consistent boundary; reconciliation per unit (`found == written + dropped_*` else loud exit); **admissions = the ledger's `distinct=True` rows, never its line count**; TWO dedup layers (any rate on raw decodes ~2× optimistic); operational failure ≠ leak. An ACTIVE cap alone does not bound wall — pair with `--wall-budget` (clock starts at LOOP ENTRY; refused in dive mode [code: `check_wall_budget_supported`]).
- **The pre-loop root draw runs OUTSIDE both caps — bounded via `--root-draw-budget`** [code]; deadline arithmetic subtracts the draw bound explicitly. Cost is set by CONTENTION, not family count — **stable at ~8.2 min of a 15-min bound two runs running, so the bound need not be generous**; ⚠ the check is BETWEEN draws, so a tight budget overshoots by up to one draw (+51% at a 180 s bound). **Size at `wall_over_active` 1.15** — realized ~1.02 on both production runs; **★ the margin covers the leg's TEARDOWN, not its loop**, and **★ apply it PER-LEG, not to the whole-run cap** [run 25: 8h/1.15 for the frontier alone leaves no room for the other legs].
- **Per-partition refill** [code: `steered_frontier.refill_starved`]: low-water fires `draw_roots` for starved partitions; cooldown + `--root-refill-share` (the ONLY bound on refill spend). **The pre-loop draw dominates any short frontier smoke** — budget wall for it; `production_seeder --smoke` has BUFFERED stdout — read `<sink>/outcome_ledger.jsonl` for progress.
- **★ A scheduler run refuses to start unseeded** — `require_library_seed()` raises; `summary.json` carries `library_seed` + a screaming `UNSEEDED_RUN` key. Seed at registered BULK (ordered REGISTRY; resolvers REFUSE scratch paths [code]); pop-quota never reads it.
- **★ SINK ISOLATION (`tools/atlas/discovery_sinks.py`) — one decision point.** `--smoke`/`--time-only` with no explicit `--discovery-dir` redirects the WHOLE discovery store to ephemeral scratch. Smoke rows are current-decode ⇒ admissible — contamination the decode firewall cannot catch. **A real experimental run is NOT a smoke — give it its own run directory.** `steered_frontier` takes an explicit `--run-dir` with no default, so it cannot fall through to the production store.
- **★ CONCURRENCY — 7 IS THE NUMBER.** (a) ONE `fractal-generator.exe` → 7 threads; (b) 4+ in parallel → think. **BelowNormal ALWAYS.** Committed defaults: `corpus_common.DEFAULT_ENGINE_THREADS` + `default_engine_env()` / `default_creationflags()` — **call the helpers, never restate the number.** `run_render_one` defaults `low_priority=True` (explorer = the one opt-out). Machine: 12 logical cores, RTX 2060 SUPER 8 GB.
- **The suite can't see the loud-late surface** → before trusting a structural change: `production_seeder --smoke` + a frontier smoke + the sink-isolated emission smoke. ⚠ **The gate-draw shakedown lane went with `deploy_tail`'s driver (`d73a6c6`) — `--ephemeral` on `build_emission_diversity_v1` is a DIFFERENT, LIVE flag**, the emission sink-isolation lane. **Reject autopsy — standing habit:** fate-stratified sheets at deploy fidelity; every readout emits numbers AND a visual sample of admissions + rejects.
- **Dive legs:** plan arms apportionment-interleaved so truncation keeps both arms [code: `interleave_dive_arms`]. **Run-record telemetry is SEGMENTED** [code: `tools/run_record.py`]: heavy jsonl streams rotate into gzipped segments + bounded plain tail; readers via `run_record.iter_rows`; assert the registry's LOGICAL stream (`run_record.exists()`), never the physical filename. **★ On CLEAN CLOSE every per-batch stream rotates to `<stem>.NNN.jsonl.gz` and the live file is REMOVED** — a post-run reader reads live + every rotation; a try/except open of the live path finds nothing SILENTLY.
- **⚠ `--seed` MUST NOT COLLIDE WITH A PRIOR SAME-DATE RUN** — a date seed replays the root draw against a store already holding that run's admissions. (Cross-run saturation memory is the LEDGERS — fractal-discovery owns it.)

## Run scratch — pruned in-run since `069feb1`
- **★★ FOOTPRINT IS WINDOW-DEEP, NOT RUN-LENGTH-DEEP.** `prune_scratch()` runs in the crawl and dive LOOP BODIES, after reconcile and after `save_state`/`save_dive_state` — **plain bodies, no `finally`/`atexit`/signal, so an interrupted run deletes nothing further** [code: `steered_frontier`]. **The rule is DATA:** `PRUNE_RULES` — `expand_b####` KEEPS `expand.jsonl`/`nodes.jsonl` and loses its JPGs; `harvest_b####` and `roots_b####_<fam>` go whole. The matching rule is a PURE FUNCTION with its own table test — **the delete is what cannot be undone, so the decision to delete is proved apart from the doing of it.** Flags: `--prune-retain-batches` (default 3, REFUSED below 1) · `--no-prune-scratch` · `--retain-scratch` (kills pruning AND teardown). `summary.json` gains `scratch_prune`, with three distinct outcomes so **"freed nothing" and "was off" never merge.**
- **Steady-state residual = window × per-batch + 18 MB, flat — ~0.8–2.0 GB at W=3, against 1.98–2.45 TB unpruned at 100 h.** Retained records cost ~1% of the expand tree (~0.29 GB at 100 h) — the price of keeping the post-run depth audit runnable, and worth it. ⚠ **Never size the saving off a short run:** a 7-batch A/B freed only 14.4% because a short run's expensive batches are contiguous at the END, inside the window; the legs with many batch-units between boundaries freed 92.6% (kill+resume) and 94.5% (dive).
- Caveats that survive: **the tally under-reports by ≤1 batch across a kill** — `save_state` must PRECEDE the prune (the safety argument), so batch N's prune reaches disk in N+1's checkpoint; the bytes were freed, only the report of them is lost. Documented at the checkpoint, deliberately NOT re-ordered · `native_<fam>/` is generation-keyed, not batch-keyed ⇒ unpruned, measured 18 MB and FLAT, deliberately no second mechanism · `production_seeder`'s own `_purge_run_scratch` untouched · **the bulk-store watch is unaffected BY CONSTRUCTION** — measured after teardown, and the pruner only removes bytes teardown would have removed first; A/B identity is the direct evidence.
- **★ NOTHING DOWNSTREAM READS RUN SCRATCH AFTER A BATCH CLOSES.** Emission re-renders each field into its own `--out/fields` off the LEDGER's coords [code: `descriptor.embed_locations`] — proved by an intake run over a run whose scratch was entirely gone; resume reads only sidecars under `run_dir`; the dive reads the source run's `outcome_ledger.jsonl`. The two real readers are `steered_pilot_morph.reconstruct_tree` (`expand.jsonl` — the KEPT record) and `morph_anchor_calibrate` (cheap JPGs — degrades to unavailable). A candidate's cheap JPG is read only inside its own batch; what survives onto the frontier is the embedding in `run_dir/node_embs.npz`.
- **★ `steered_frontier` STILL TEARS DOWN ITS OWN SCRATCH ON CLEAN CLOSE** [code; an INTERRUPTED run never tears down] — `storage_classes.md` §5.6: a per-run bulk producer owns its teardown; teardown now finds less to delete. **20.7–29.8 GB/h is the UNPRUNED draw range** (runs 26/27; supersedes the ~18 GB/engine-hour point figure), and **the trough-hangs-off-teardown framing now applies ONLY to `--retain-scratch` / `--no-prune-scratch` runs.**

## Stage profiling (`25ab4e9`) — DURABLE ON BOTH LEGS since `e7d7c8c`
Classes + homes → fractal-storage. `stage_times.jsonl` per unit of work — one writer (`tools/stage_times.py`), one schema, eight record sites across both legs, session totals in each `summary.json`. **Nothing reads it back in-run and no cutoff consults it — zero behaviour change is STRUCTURAL, not a claim.** Reader `tools/run_profile.py`: **rank by ratio to a unit's OWN stage median, never by seconds** (>3× flagged; seconds returns the release renders every time and buries the colorize attempt that took 30× its peers), no flags under 5 units, and it cross-checks per-unit totals against the run's aggregates — **that pair disagreeing is a batch that ran and was never charged, which nothing else in the record would say.** Run-26 baseline BACKFILLED off console logs (`t_end` OMITTED rather than invented ⇒ run 26 has no span at all). **Tail concentration is a TUTORIAL-ERA WATCH: 54.5% of the leg in batches over 3× median, from run 26's 61.8% — the flatter tail is the direction to keep.**
- **★ BUDGET ARITHMETIC — budget a leg off an OBSERVED LEG, never off a rate.** The emission leg is **≈90 min at `--release-n 12`** — intake 56.6% / release renders 34.3% / colorize 9.1%. The shakedown's 94.9%-intake figure was a `--release-n 2` artifact, and its "~29 min uncontended" intake understated the leg ~1.9× by extrapolating a FILE RATE. Intake is independent of `--release-n`; the release renders emphatically are not. **A dive leg's FIRST dive is unbounded by `--budget`** (`est_batch_s` is 0 until one completes).

## Release-pass workers (`ee4122f`) — ADOPTED, first live run pending
`--release-workers`, default **3 workers × `DEFAULT_ENGINE_THREADS`** [code: `tools/emission/release_pass.py`]; `1` = the untouched serial path (kept distinct; real-engine parity test cross-checks the two). Structural rule: **workers render, the PARENT alone writes every record in PLAN order** ⇒ concurrent outputs byte-identical to serial, attribution counters untouched. Workers self-assign Windows job objects (`KILL_ON_JOB_CLOSE`) so a hard-killed worker takes its engine child; a DEAD WORKER (vs a failed row) breaks the pool once → remaining rows render serially in the parent, announced. Surviving rules: **realized ceiling ~1.5× — NOT core-count math: Σ row-seconds inflates under concurrency (the bandwidth-bound tail, one level up)** · **nominal oversubscription BEATS dividing threads among workers at every N measured** · the RAM-heavy axis is the phoenix FAMILY, not composites, and RAM does not bind at w3–w4 · w4 ties w3, rejected on RSS + process count. ⚠ Sweep n=1/arm (one arm n=2, 1.6% spread). **Never yet run inside a real `build_emission_diversity_v1` — run 28's emission leg is the shakedown (state §OPEN 2).** Mechanism + sweep tool → `docs/design/release_concurrency.md`.
