## Laws
- **★★★ A LABEL ROW CARRIES ITS JOIN.** Label + complete render block/params in the SAME tracked row; a label keyed on an id whose meaning lives in an untracked file is orphaned when that file dies (proven three times). Labels ship FLAT: label + join + batch id + registration flags; eligibility DERIVED, never stored per-row.
- **Export/ingest discipline:** the `labels\` drop is untracked — **THE INGESTED STORE IS THE COMMITTED RECORD; ritual = export → ingest in the SAME session**, count-verified, both stores, pin asserted before and after [code: intake.py `assert_pin`]. Sheet units are numbered by position — a rebuilt sheet renumbers.
- **Canonical reader = `store.resolved()` / `finished.resolved()`** [code: labeling/store.py] — never write another, never infer labeling state from raw image lists. Originals never modified; a revision is a later row, LATEST-WINS by `(recorded_at, file, line)` — `labeler` is not in the key. No amendment overlay exists in this repo (the maker-era overlay was applied ONCE at `corpus_import`).
- **★★ THE SCALE IS 1–4 FOR EVERY HEAD; class 4 is just a class.** Anchor sheets DEFINE each bar (the ckpt-51 sitting's anchors = the strange 4 bar). Store scale is DECOUPLED from model class count [code: finished.SCALE · RECIPES · finished_import.SOURCE_SCALE; pin asserted per run; a recipe that cannot express a population verdict REFUSES to train]. Imported rows' ceiling sits on SOURCE_SCALE.
- Location label = max over crops; `decoded_class` ≠ human label. Multiple render regimes coexist — the labels hold.
- **★★ `labeler:null` = MATT'S LABELS** (maker-era import); Matt is the ONLY human labeler. **Label-origin rules protect exactly two things — eval-split integrity and taste attribution; when neither is in play, a label is a label.**
- **Any row with `scores.p_ge4 == null` is on the retired 3-class scale — evidence of nothing current.**
- **★★ LABELING IS AFFORDABLE WHEN WE NEED IT** — size for power; renders, not labeling, price a batch (~6.3 rows/min labeled). **★★ LABELS MUST SERVE OBJECTIVES THE NEXT RETRAIN CANNOT DEPRECATE** — eval instruments, design reads, correction sittings pass; training volume fails by default. Never add calibration duplicates, drift probes, or repeat rows (settled). **★ Don't editorialize on a sheet about to be labeled blind.** A prompt running while Matt labels conflicts on GIT, not CPU — commit only its own files by explicit path.

## Sampling regime
The split-registry rulings are SETTLED → `settled_rulings.md` §Corpus sampling [code: registry.UNREGISTERED · registry.refuse_contradiction]. Laws that still change a read:
- **★★ The disqualifying bias for an EVAL set is MODEL-DRIVEN SELECTION, not non-randomness** — a systematic grid or base-rate draw is eval-eligible; candidates a model scored well are not. **★ Nominal splits are not realized splits** — check realized shares before quoting a CI. The in-repo registry is the authoritative roster; caveats → `data/batch_caveats.md`; **register a new generation method BEFORE its batch is built.** **⚠ A NAIVE "anchored AND representative" FILTER IS NOT AN ELIGIBILITY RULE (ckpt 85)** — it admitted the `p_ge4_calibration_*` batches and moved smooth's apparent clean ≥4 rate from .091 to .255 in a single commit. **Eligibility is DERIVED, never stored, from THREE fields: `eval_only or (score_unconditioned and not anchored)` [code: `registry.py` `Registration.eval_eligible`].** `eval_only` is a PIN, not a third fact about the draw, and it outranks: both shipped instruments are eligible SOLELY by it and would be train-side under the two-flag rule. **⚠ REGISTRATION ALONE DOES NOT PIN (ckpt 88)** — the pin is `eval_split.jsonl`, written by a deliberate split step, and **`label ingest` never refreshes the pin document**, so a newly registered `eval_only` batch fails the store's own guard two ways: leave the split stale and `eval_only_batches` no longer matches the pinned rows, extend the pin to every place and older TRAINING rows are stranded on the wrong side. Resolved as the store's refusal names it — **fix the split, never the pin**: pin only the places carrying no training row, leave the contested ones unpinned, and assert the new side is a superset of the old before writing, because `write_pin` TRUNCATES. On the ckpt-88 sheet that was 150 of 200 pinned, 50 contested. **⚠ The guards catch CONTRADICTION and OMISSION, not correction** — an in-place edit of a standing registration moves a batch's side with nothing red, and no test compares a shipped split against a changed registration. **★ A ROW MUST LAND IN THE STORE ITS MODE ROUTES TO** — 40 `rare_palette` rows sat in `strange_render` under mode `smooth`, ranking second by ≥3 rate in a store that does not judge it; now refused at write and excluded at the training read, with the stored rows themselves untouched [code: `finished.check` · `finished.routed_to` · `finished_train.population`].
- **★★ A BLIND SHEET INFORMS EXACTLY ONE BOUNDARY, chosen by its draw's quality conditioning.** Blind sheets are eval-only forever. Anchored sheets measure AGREEMENT with the incumbent; a rate off any prefilled sheet is a CEILING.
- **Standing blind instruments (data):** blind_minibrot (≥4; its ≥3 rate is the GATED intake's base rate) · blind_modes (gate ≥2/≥3 freely; **≥4 has zero blind positives — NEVER read it; guarded in the suite**). **⚠ smooth ≥4 order on blind_minibrot is ≈ chance for BOTH the retired and shipped judge (AUC 0.56, n=197)** — the smooth rank key is weakly resolved on that population; eyeball gallery seats before building any instrument. No instrument covers smooth ≥3 or a phoenix:classic base rate — build one WHEN a decision needs it. An anchored strange verdict at a blind_modes-pinned location is WITHHELD by the store rule (9 such rows, correctly unused).

## Judge method (governs every retrain)
- **★★ THE WINNER RULE:** candidate only if (a) no overall pre-declared metric significantly worse (95% paired bootstrap) AND (b) the motivating slice significantly better, none worse; declare slices before numbers. **The raw scoring-rule arm STANDS (ckpt 76): a scale-only failure with order intact is a CAPACITY/RECIPE signal before it is a data signal — check the realized recipe before explaining the numbers.**
- **★★ NON-INFERIORITY READS THE BAND:** for parity-motivated candidates the bar is "no pre-declared metric significantly worse ON THE BAND"; a per-seed conjunction is a multiplicity trap — any future per-seed conjunction PRE-STATES its false-alarm size at registration. **★★ Cross-seed comparisons score the BAND, never the staged pick alone.** **★★ The model-selection objective is a CONTROLLED VARIABLE** — freeze selection to the baseline-comparable population; amendment before the re-run.
- **★★ CORN scale is train-prior-calibrated** — a retrain moves the whole probability scale. **TWO RESTATEMENT MODES when a cut must survive a head flip:** VOLUME-MATCHED (same fraction of a fixed reference pool) · HUMAN-DERIVED CROSSOVER (isotonic P(≥boundary)=0.5 on a labeled sheet; the volume change can BE the finding). Every adoption splits its causes (rows vs scale) by re-fitting the retired artifact over the grown stores first.
- **Test construction:** a reproducibility test re-runs the writer the artifact came from; NEVER construct a test's expected value with the transform under test — a planted red proves the guard bites; a pre-declared bar must OUT-RESOLVE its instrument — a teacher's self-agreement is a ceiling, never a bar.
- **The declared-recipe law** (→ fractal-operating) is GUARDED here [code: `check_declared_backbone` at launch · `check_written_backbone` in `render_acceptance.read`; `render_train.MISLAUNCHED` holds the three medium runs, out of every band]; compare a shipped artifact's size to its predecessor's as a free check.
- **A head's render cache must be COMPLETE against its stored rows before it trains** [code: `renders plan` / `renders build`]. The location head is REGIME-ROBUST (`seed0_all_regimes`, `f8f80511`, weights-v2, adopted 2026-08-20): **one score SCALE across regimes, not one NUMBER** — never read a cross-regime delta ≤0.3 as a model change (→ fractal-discovery §Regime law).
- **★★★ THE RENDER JUDGE IS A GATE, NOT A TOP-END RANKER (ckpt 85) [human n=246, two stores, four strata].** Inside `P(≥4) ∈ [0.60, 0.95)` it barely orders Matt's 3-vs-4 verdict: realized logistic slopes 1.75–2.47 where the design assumed 12, point-biserial r 0.11–0.18 with one stratum negative, and **no ≥4 crossover identified in any stratum** (intervals 0.20–0.45 wide against 0.08 resolvable). Replicates the AUC 0.56 smooth ≥4 result on four new populations. **A cut inside that band mostly discards Matt's own 4s** — 0.90 rejects 77% of them while still admitting 20% of his 3s — and **hard optimization of the score there is optimizing noise**. Every in-band row came back ≥3, so the ≥3 crossover sits BELOW 0.60 and is unmeasured. **★★★ BUT THE CEILING IS NARROWER THAN THIS SOUNDS (ckpt 86, grouped holdout): unbanded, over the 209 held-out rows a human scored 3 or 4, the head orders them at `AUC(≥4)` 0.650 — 3-vs-4 is NOT irreducible from the picture.** What resists is ordering INSIDE the head's own uncertainty band: rows land in [0.60, 0.95) because the head cannot decide, so conditioning there strips most of the score variance an AUC reads, and the shipped head — which memorized those rows — is at chance there too. **A band-restricted null is weak evidence; the unbanded 3-vs-4 read on a larger holdout is the better instrument, and it is what the next bar is declared on.** **The one resolvable calibration: at matched score a composite is +0.249 [+0.051, +0.446] more likely to be a 4 than a thin-colour candidate** — thin colour is WORSE than its score, not better, so relaxing a bar for a thin cell compounds the error.  
- **★★★ THE `P(≥4)` COLUMN IS A WELL-CALIBRATED ≥3 SCREEN WEARING A ≥4 NAME (ckpt 88, human n=200).** Calibration gap **+0.573** absolute on `P(≥4)` (mean predicted 0.9625 against 0.390 observed, Brier 0.571) against **+0.060** on `P(≥3)` (Brier 0.066). A threshold sweep inside a selected population keeps 149/81/47/22 rows at tier-4 precision **0.309 / 0.309 / 0.298 / 0.364 — flat across four decades** — while the same sweep on ≥3 climbs 0.913 → 0.975 → 0.979 → 1.000. **No threshold on this column buys tier-4 precision; every threshold buys ≥3 purity.** `AUC(≥4)` inside the seats is **0.499**, and the head ranks the MIXED page (+0.211) but neither block alone (seats +0.127, control +0.169, smooth seats −0.115). **★★ A STATISTIC THE HEAD DOES NOT USE BEATS IT AT ITS OWN TOP:** a map's own prior human label history predicts tier 4 inside the seats at **AUC 0.643** where `P(≥4)` reads 0.489 — available today, no weights, no retrain. ⚠ **Neither reading predicts better** — `columns` (1280×720) against `selected_on` (640×360) is `AUC(≥4)` 0.499 vs 0.495 in the seats and `AUC(≥3)` 0.834 vs 0.833, and the rows that MOVE between regimes carry no signal in size or direction. **The seating regime is not the wrong one to select in; the problem is not where the head reads but what it reads.**
- **★★ THE RENDER JUDGE IS NOT REGIME-ROBUST.** Across one doubling of geometry `P(≥4)` is UNBIASED and IMPRECISE — mean −0.009 sd 0.087 on the mid band [n=133], +0.011 sd 0.065 over the full range [n=396], Spearman 0.915, and 46% of mid-band rows change 0.10-wide band. Re-levelling adds to it (spread 0.123). **Fit and read on the LABEL-GEOMETRY column, never the candidate one.** **A prereg's POPULATION is load-bearing** — measure a decision on the population it serves.
- **Division of labor:** the location head STEERS within-family and NEVER ranks cross-family (and picks FRAMING within one location → fractal-discovery) · **ONE render judge (`render`; identity and tag → fractal-tutorial)** scores FINISHED renders of both kinds · the palette head picks palettes within a location, never quality (its split keys on LOCATION — settled) · steer/rank/select stay split. **smooth/strange are KINDS**; `smooth_render`/`strange_render` name the two LABEL STORES (two corpora, two blind instruments, two base rates, two floors) but no model. **A shared nominal scale does NOT license cross-kind ranking** — pools disjoint, floors per kind. Two training runs at once ≈1.7× throughput (data-loading bound).
- **★★ THE RETRAIN'S EVIDENCE IS A GROUPED HOLDOUT, NOT A BLIND SHEET (ckpt 86).** Strange-side calibration has failed repeatedly; a held-out split answers "does B rank better than A" directly. **⚠ THE DEAL IS FIVE FOLDS AT 20%, NOT FOUR AT 25%** (a prompt assumed four and would have left a fold unfitted). **★ DECLARE THE MOTIVATING SLICE ON THE WHOLE STRANGE POPULATION, NEVER THE 3-OR-4 SUBSET (ckpt 87):** the same effect is +0.0414 [−0.0103, +0.0945] on 209 subset rows and +0.0393 [+0.0048, +0.0776] on 714 whole-population rows, so a slice declared that way is a strictly weaker version of one of its own non-inferiority guards. **The `P(≥3) = 0.5` crossover refits out-of-fold at 0.5693 [0.504, 0.642] against the acting `STRANGE_RELEASE_BAR` of 0.575 — the first independent check that height has ever had. There is NO ≥4 bar at any height, and per-mode crossovers span 0.367 to 0.950, so per-mode bars are mandatory** (→ `preserve\selection_design.md` §Greedy-first selection). **Group on LINEAGE = `family` + `viewport`, no join needed, assigned over the POOLED corpus** — 295 groups hold rows of both kinds carrying 4,181 rows, so a per-store grouping leaks across the kind boundary [code: `labeling.groups.assign`]. Score on AUC, never probability agreement: a retrain moves the whole scale by construction. Settled this era: **the cause is not ROWS** (arm A refit on the grown stores is at chance in-band, 0.502 against the shipped head's 0.518) · **not CAPACITY** (the MISLAUNCHED medium band is 3.3× the parameters and peaks at the same selection-slice `AUC(≥4)`) · **not TOP-BOUNDARY REWEIGHTING** (`corn_loss` already averages each cutpoint's own mean, the sqrt sampler already reaches 2.28× of the 2.67× a full inverse balance could, and a CORN classifier is one `Linear` whose rows do not interact — the only shared thing is the TRUNK, and a weight is not a lever on a trunk). **⚠ `top_cutpoint_selection` is a DEAD END — never retry:** a proper scoring rule read at one rare cutpoint is minimized by an under-confident head, so it chose epoch 1, bought earlier stopping rather than better ordering, and cost the smooth side significantly. **Both were GRADED at ckpt 87 and the method, the costs, the dead ends and the adoption checklist now live in ONE place — `preserve\judge_training.md`, which must be read before specifying any retrain. Two results that change a future read: **`input_detail` at 768×448 is a real +0.0393 on the whole strange ≥4 boundary [+0.0048, +0.0776], seed-stable, clearing every guard — and was NOT adopted** (deferred on cost; the re-entry instrument is a candidate-geometry check, since 768×448 exceeds the 640×360 candidate column). And **⚠ `AUC(≥4)` does NOT peak at epoch 11–13** on a lineage-grouped stop slice — it peaks at 5 or 6 every run, so never re-quote "87% of each run's wall is past the kept epoch". The stopping rule buys **variance, not mean**: +0.0064 on the motivating slice, but epoch 5–6 every run where cross-entropy swung 2, 7, 6, 4.
- **★★ THE CORRECTION LOOP IS THE LABELING METHOD** (mechanics → `labeling/README.md`; assume proper randomization — a distribution concern is ≤1 line). Laws kept here: suggestions come from the SHIPPED `render` head via `floors.SCORING_HEAD` — re-check every load site after any judge adoption · sheets are cut ORDERED BY P(≥4) · **~500 rows per sitting, then VERIFY the labels earned their keep** · anchor first for a fresh scale · a stated RULE answers a unit BEFORE it renders, rule verdicts DERIVED never stored, **never pool readouts across rule ids** · sheet render cost tracks GATE STATUS + DEGREE, never maxiter or pixel count — **pilot per-class ON the target population** · per-sitting correction rate = the head's report card (a CEILING); on modes a head has never seen, agreement is NOISE. **★★ SHEET CONSTRUCTION (ckpt 85):** a sheet renders at `LABEL_RESOLUTION` 1280×720 ss2, the geometry both corpora were collected at, and a sheet is ALWAYS a fresh render; score every sheet picture at label geometry too and carry BOTH readings on the row (new row key `selected_on` carries the reading the row was SELECTED on). **⚠ "candidate caches give ZERO hits" is POPULATION-DEPENDENT, not a standing fact (ckpt 88)** — on a page drawn from already-worked places, 25 of 200 rows would hit; `finished_source` refuses the cache only where the operator levelled. **★★ ONE POPULATION SPANNING BOTH KINDS IS TWO SHEETS** — `finished.check` routes by `hunt.kind_of`, so a mixed page is two sheets, two registrations and two ingests. **⚠ AUTOLEVEL IS INVISIBLE ON THE ROW:** the ledger drops `acted` by design, and on one 200-row page the operator actually fired on **85 (43%)** — built straight off the plan, those 85 would have served a different picture under the same identity. A measure pass at label geometry is what answers it. **⚠ `finished_source` writes `facts`, `columns` and a caption UNCONDITIONALLY and the page renders all three, so "no editorializing" is not a flag** — `sheet.jsonl` must be rewritten with them emptied. `p_ge4_calibration_*` shipped with the mode name and the score on the card and was labeled that way, which makes its near-null discrimination CONSERVATIVE rather than void, but it is not a clean-blind sheet. **⚠ `--port` walks upward silently** — read the banner, never the command line.

## Label noise — what it forbids
Disagreement is adjacent-category only: a real ordinal scale with a fuzzy boundary, not a learnability ceiling. **Forbids reading small AUC differences on the ≥3 boundary.** Pre-register bars before computing; verify the instrument's inputs actually change.
