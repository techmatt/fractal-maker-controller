**★★ SINGLE-HOME.** Grep each bolded numeral across emitted docs and assert single occurrence; other docs NAME a fact and cross-reference, never restate — preserve docs included.

**★★ TAG CLAIMS ABOUT CODE.** A line asserting what the tree does carries `[code: path]` or `[unverified]`; a claim of AUTOMATIC FUTURE BEHAVIOR names the enforcing mechanism or is not written. Every checkpoint that checked has falsified some untagged claim.

## STANDING POSITIONS (Matt, firm)

- **★★ RUNS ARE PRODUCT; LABELING IS AN EVAL ACTIVITY (2026-08-13).** Runs are on Matt's schedule with no verification homework. **A LONG RUN (100 h+) MUST NEVER REQUIRE LABELING IN THE LOOP.** Labeling re-anchors the books when it happens; high-value sources ACCUMULATE (fractal-corpus). **Retrain when a decision needs it, NEVER preemptively.** A run whose allocation depends on fresh human labels is refused.
- **★★ THE CLEAN-REPO MODEL (2026-08-14).** Fresh repo = everything pulled in cleanly, CONTEXT-FREE; labels FLAT; NO byte-identity requirement — cleanliness over byte-identicalness; shipped weights trained WITHIN the repo. Editorial line: *"this is about fractals, not ML."*
- **★★ NO ARCHAEOLOGY; DELETION IS NORMAL.** Don't resurrect artifacts that don't match how things work now; retention is Matt's, outside the repo. **★★ USEFULNESS BEFORE RECOVERABILITY** — if nothing will want it back, delete the regeneration machinery with the data; regenerability is not per-file when builds are chained.
- **★★ NOTHING LOAD-BEARING LIVES IN `scratch/`, both ways** — evidence leaves it when it justifies a decision; a proposal computed there never leaves as a fact. ⚠ **There is NO enforced allowlist (ckpt 89, checked in tree)** — this is a discipline, not a guard, and these docs asserted an enforcement that does not exist. Matt wipes scratch between checkpoints.
- **★★ A DURABLE RECORD WRITTEN AFTER A FALLIBLE STEP IS NOT DURABLE** — irreplaceable record first. **★★ LOSING HAND-LABELED DATA IS A MAJOR FAILURE** — nothing rewrites, deletes, or re-keys stored label rows; re-attribution is reader-side; verify exports BY ROW COUNT. **★★ A TEST FIXTURE IS WRONG ABOUT WHAT IT ISOLATES UNTIL PROVEN (ckpt 89, three times in one era)** — a merging test must redirect FIVE paths (rows, scores, backup, manifest dir, flatness sidecar) and redirecting fewer clobbered this machine's real archive copy with a 48-byte file; a seating fixture naming pictures that were never on disk left the twin rule silently inert across 22 guards. **A tracked RECORD is never edited in place** — fix the reader's semantics, or add an amendment the reader prefers beside it. ONE exception (ckpt 75): a split REGISTRATION is a pre-build DECLARATION, not an event — a contradicting row is REFUSED at write and read, so a wrong registration is corrected in place [code: registry.refuse_contradiction; tests/test_label_registry.py].
- **★ REPO-DOC ADMISSION:** something in the code owns it and it stays true as the code changes; a transient measurement lives in scratch — survivors extracted, source deleted — **an extraction that does not delete its source is the failure; a rule nothing enforces is not a rule — name the guard.**
- **★★ THE 10,000-HOUR FRAME (Matt, 2026-08-22)** governs every product decision — *judge every choice by "what makes the best-framed, highest-quality, most beautiful, most diverse wallpaper collection given 10,000 hours"; anything that discards and never revisits is generally bad; err toward over-admitting whatever could possibly be good and let the embedding and the solve reject near-duplicates*; pacing-never-rejection → settled_rulings. Don't over-think trivially small counts. **★ A DANGLING REFERENCE IS NOT A TASK** — a line that sounds like a task but names nothing in any repo fails the deletion test.
- **★ A RULE'S PURPOSE BOUNDS ITS SCOPE (ckpt 65).** Before refusing or redesigning on a rule, name what it protects; if that is not in play, the rule is not either.
- **★ TWO SPELLINGS OF ONE FACT IS A SILENT NULL (ckpt 70).** One adapter, one key, the reader asserts the spelling it expects; a witness on the wrong axis understates a gap.
- **★ A DECLARED DESIGN THE LAUNCH DOESN'T READ IS NOT THE DESIGN (ckpt 76).** Guard two-ended — launcher reads the declaration, reader refuses a disagreeing written config, a planted mismatch fails; an artifact's size against its predecessor's is a free check. Explain a surprising result only after the realized recipe is verified. Training-side guards → fractal-corpus.

## REASONING & MEASUREMENT

**Confidence convention.** Every verdict carries **basis** (`[human n=X]`·`[machine-decode]`·`[measured]`·`[inferred]`·`[by-eye]`), **population**, **overturned-by**. No falsifier = a belief; `[machine-decode]` is evidence about the MODEL, not the world.
- **★ Cuts and floors are RELATIVE TO A REFERENCE, never absolutes.** Every precision in a lock or anchored rate is a CEILING.
- **★★ NEVER POOL ACROSS AN ESTIMAND CHANGE. A REGENERATION MOVES EVERY MEASURED ROW** (partial adoption = hand-splice). **A DEFAULTED SEED IS A BAND**, not a neutral prior.
- **★★ PRICING.** (1) BUDGET A LEG OFF AN OBSERVED LEG, never off a rate — rate extrapolations understate ~2× (bulk small-file moves ~3×); stage anomalies rank by ratio to the unit's OWN median. (2) A PROMPT'S PRICE IS THE MEAN OVER THE REAL POPULATION (ckpt 80, twice: a median where a maxiter tail was the cost; a number carried from a pass that had reused a stored artifact) — name the population and the statistic, or say "unpriced". (3) COST TRACKS WHAT THE PIXELS DO (ckpt 70) — pilot on the target population before sizing any leg; a prior from another population has been wrong by an order of magnitude; price a REMOVED render/IO line against a COLD cache. (4) **MAXITER DOES NOT PRICE A PARTITION, AND THE MODE PRICES A CANDIDATE AT LEAST AS HARD (ckpt 83–84)** — phoenix is the dearest partition on the second-cheapest cap (3.32 s at median maxiter 10,213 against mandelbrot's 3.16 at 25,239); composite modes are 51.8% of the bill on 35% of candidates, and `smooth_curvature` is 7.6× `itinerary` inside one partition. Every partition's median is under half its mean, so a mean over a mode draw is a mean over a bimodal population — **size a budget on candidates × partition rate × mode-kind rate**. (5) **⚠ `time.monotonic` HAS A 15.6 ms FLOOR ON WINDOWS** — invisible against a 1.26 s render, half a stage against a 31 ms recolour; any recolour-scale profile taken on it is void. (6) **A FILENAME THAT ENCODES A SPLIT IS NOT AN IDENTITY** — a chunked resume must subtract MEASURED identities (a sweep skipped 5,524 of 13,020 pairs per location while reporting success), and an estimate off another population's rate ran 2.5× over because composites scale superlinearly in maxiter. (7) **⚠ A CONCURRENCY RATIO IS NOT A SPEEDUP (ckpt 89)** — engine-seconds over wall read **2.94×** on a leg delivering **1.92×**, because an engine sharing the machine costs 1.57× more per candidate and that inflation counts as work. Candidates per WALL second against a serial arm is the only figure that means anything, and a rate read off a concurrent leg over-prices a serial one by ~1.6×. **A budget clock starts at the first unit of WORK** — a deadline of `started + budget` put a 25 s pilot 17 s past its deadline before a worker was handed anything.
- **★★ A "BYTE-IDENTICAL" CLAIM IS PROVEN BY RUNNING THE REAL COMMANDS** — and scoped to the module compared. Test-construction and bar-vs-instrument rules → fractal-corpus §Judge method.
- **★ VERIFY FROM CODE, NEVER FROM A SIBLING SURFACE (ckpt 74)** — docs ↔ site ↔ code consistency is proven from code; a LIBRARY fact is not a PIPELINE fact; a feasibility verdict answers ONE parameterization — check it against the decision's own parameters before relaying. **★ NAME THE ENTRY POINT THAT IS ACTUALLY IN PRODUCTION BEFORE AUDITING IT (ckpt 87)** — two audits in one era each had to correct the command the docs named before they could answer anything, and the docs had described a loop carrying 0.8% of the work for two eras. Confirm from the records which code path made the rows, not from what the docs call it.
- Judge-method and split rules are OWNED by fractal-corpus — point, don't restate.

## WORKING STYLE

**One CC prompt at a time PER REPO** — different repos concurrent by default; same-repo parallelism only when verified (overnight wait-gate queueing; a second CC beside a GPU-bound wait; read-only audits beside anything). **⚠ SAME-REPO CONCURRENCY IS NOT FREE EVEN UNDER EXPLICIT-PATH COMMITS (ckpt 85)** — a beside-running prompt's commit swept up the other's README additions despite the instruction; assume a shared commit, and never pair two prompts where either writes a tracked file the other touches. **★★ A website prompt that may touch the engine LOCKS BOTH repos (Matt, 2026-08-21)** — check in-flight state across both and say so in the header. Engine carve-out for wasm consumers → fractal-tutorial §WORKFLOW. Progress-through-delivery over method minutiae; scope narrow; diagnosis-first is NOT a standing policy. **★★ RUN DURATION (Matt, 2026-08-28 — the N−2 reserve is DELETED; never apply a default overhead reserve).** "An N-hour MINE or CRAWL" — any producing leg — means **N hours of THAT LEG**; build, merge, readout and report sit OUTSIDE the number, unless Matt clarifies for that prompt. **"Finish by X"** names the ENVELOPE and includes setup and readout: reserve the build and report actually expected for that prompt, STATE the reservation in the prompt so Matt can correct it, and size the leg to land on the deadline. Ask when a case is ambiguous. The budget is a TARGET, not a cap. **One run per budget — a follow-up of ANY length is a NEW budget question.** **★ EXPLORATORY ~8 h RUNS: ONE PROMPT COVERS LAUNCH AND POSTMORTEM** — CC stays up across the run and writes the readout; separate readout prompts only as follow-ups; not for ~100 h runs (Matt, 2026-08-22).

- Prompts = short `.md`, presented AND delivered; length scales with risk; trust CC on mechanics. **★ CC's honest spec-deviations with stated reasons are consistently right — read before overriding.** Supply claims to be CHECKED, not transcribed; ask for the corrections back. **★ AFTER A REPORT, DO NOT SUMMARIZE IT BACK** — say what it CHANGES, what Claude got WRONG, what's next, plus a short "carry:" delta of what the docs must change; trivial outcomes ≤2 sentences (Matt). **★ NO "UNREVIEWED BY MATT" TRACKING** — assume CC's calls and the rendered state are fine until Matt says otherwise; flag only decisions that BLOCK upcoming work. The site is DRAFT — argue toward the right FINAL PRODUCT, never from churn.
- **★ NEVER EDIT A PROMPT ALREADY HANDED OVER** — addendums. Matt does NOT hand-edit JSON/config — he dictates, the prompt applies. Acceptance BY EYE except classifier evals. Git — commits, push, remotes — is his entirely; never flag or mention its state.
- **★ A FIX WITH A SHAPE NEEDS THE PROMPT, NOT A "YES."** **★★ AUDIT-FIRST:** when a task needs technical knowledge the session lacks, STOP and ask Matt whether to send a facts-only audit prompt — never scaffold load-bearing content around CC-fill spots (accepted exception: a placement-time verification list at the foot of a draft, which CC corrects from source and reports); audits report facts, the session authors prose. **★★ REPLAY FIRST:** for any selection rule, replay the last pass under it before building (ckpt 80: a read-only replay found four shape errors in a Matt-ratified design). **★★ AN EYE-CHECK PROMPT NEVER STOPS (Matt, ckpt 80):** it always delivers the sheet; on a failed derivation it takes the least-bad choice, says so, and still renders — "I can't do anything from text." **★ A BULK APPROVAL IS NOT PAIR VERDICTS:** a block approval is one mark, not N; derive constants only from marks Matt actually made, and put the pairs the derivation turns on in front of his eye. **★ A POLICY FLIP ASKS "WHO ELSE APPLIES THIS DECISION?"** — grep for private copies. **★ BUILD ≠ FLIP** — staged in one prompt, adopted in another against a pre-registered bar. Non-negotiables bought by disasters: pre-registered eval bars · blind human reads of any model-selected population · reject autopsy + identity round-trips. **Reject autopsy — standing habit:** every readout emits numbers AND a visual sample of admissions + rejects.
- **★★ QUEUE ORDER COMES FROM DEPENDENCIES, NEVER FROM WHAT IS ALREADY RULED (Matt, ckpt 76).** Ask what X needs and what needs X — a build whose benefit lands later still costs nothing to build now.
- **★ Name full paths in any delete/move instruction** — "delete v7" is a version, not a path.
