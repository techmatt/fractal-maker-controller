Discard-and-never-revisit is bad; over-admit and let the embedding and the solve reject near-duplicates. Don't over-think small counts. ⚠ **It is a JUDGEMENT rule and never a storage projection** — the real remaining horizon is about 100 more mining hours (Matt, 2026-09-12), and reading the frame literally against disk is a category error.

If absurd, fix the design now. A file read in full carries a stated bound; retention that drops the picture drops the row; per-render facts go in counters or run records. A leg's own measurement record retires WHOLE, never pruned by row.

Claude does not track lanes at all (ruled 2026-09-09): slow lane OFF in a prompt unless Matt names it; never flag it as owed, never chase a paired reading or a collected count.

## WRITING A PROMPT

**Delivery.** Every prompt is a short `.md`, presented AND delivered as a confirmed Drive create into `prompts\` in the same turn — presenting alone is not delivery. **A delivered prompt is never edited** — corrections are addendum files (`<prompt>_addendumN.md`, "paste with the original"). **★ A PROMPT NAME THAT COULD RECUR IN A CYCLE CARRIES `_ckptNN_`** — the date alone cannot separate two closeouts in one day, and `prompts\` has twice held two files of one name.

**Shape.** TARGET-REPO guard first (`fractal-wallpapers` / `fractal-website` / `fractal-maker` / `fractal-maker-controller`), STOP on mismatch; "Commit when done." last unless it says why not. Each repo's `CLAUDE.md` owns the standing contract (report path/shape/delivery, README promotion, concurrency, backgrounding, the commit gate) — never restated. Wallpapers' `CLAUDE.md` carries BOTH a backgrounding rule and a commit gate (verified 2026-09-05; these docs said otherwise for weeks and every prompt restated them). Length scales with risk; trust CC on mechanics. **State the goal; the anchor is a hint** — authorize CC to normalize whitespace, repair a near-miss anchor and resolve a contradiction between two of the prompt's own instructions, reporting what it chose; STOP only for a genuinely ambiguous target. Every append checks the fact isn't already there. Full paths in any delete/move; state the new names for what moves; instruct verify-from-source over these docs. Matt dictates config values; the prompt applies them. Never mention git push, remotes or commit state. **A prompt that stops a leg kills its OWN workers by pid, never every engine on the box**.

**★ EVERY PREMISE IN A PROMPT IS A CLAIM, VERIFIED FROM SOURCE BEFORE IT IS ACTED ON — THE MOST LOAD-BEARING HABIT OF THE ckpt-125 ERA.** State premises AS premises, say what the prompt does when one fails, and make every fallback a branch the source decides — never a remedy the premise licenses. A prompt's own figures are the least trustworthy numbers in it; a count that decides a plan is read live at launch.

**★ AN UNATTENDED PROMPT NEVER CONTAINS A STOP-AND-ASK GATE (Matt).** The wrong-repo guard is the only STOP; every other gate is a branch — do what fits, record what didn't, continue — and the prompt says so up front. Stop time may arrive in the launch message. Exception: a closeout apply-script's STOP-on-failed-match. **★ AN UNATTENDED PROMPT NEVER CARRIES A WAIT-FOR-ANOTHER-REPO CONDITION (ckpt 126, a nine-hour night lost).** "Do not start while X runs" is a handover gate, and a gate CC must WATCH is a stop-and-ask in disguise. Matt launches an unattended prompt when the repo is free; if a wait is unavoidable the prompt names the polling mechanism (a backgrounded loop on the real condition), never an intention. CC's own rule now: the trigger for arming a waiter is *my next step waits on a condition*, not *I launched something*. **An eye-check prompt never stops either** — it always delivers the sheet, taking the least-bad choice and saying so.

**★ ONE COMMIT AT A TIME PER REPO.** Repos run concurrently; two prompts in one repo only when one will not commit while the other might, never when both write a tracked file. **A prompt that runs BESIDE another in the same repo writes nothing tracked, holds no pool, and OMITS the commit line** — reports live in `scratch/` + Drive `reports\`, never in git, so the only collision is the `git commit` itself. **No second committing prompt starts while another has uncommitted changes; a clean `git status` that holds for a minute is not a handover.** **★ A WEBSITE PROMPT LOCKS THE WALLPAPERS REPO ONLY WHEN IT BUILDS THE WASM OR COMMITS INTO THAT CHECKOUT (ruled ckpt 116)** — the website repo's engine carve-out commits next door by explicit file path, never `git add -A`, precisely so that it does not need the lock. Running `builder check` is a different thing and is covered by the pool-adjacency rule below. Say which of the two a prompt is, in its header. **★ THE ENGINE CRATE COUNTS AS WALLPAPERS (ckpt 140): a website prompt whose engine-crate edits sit unstaged next door IS the wallpapers prompt in flight — no wallpapers prompt launches beside it** (the Phoenix engine edits ran beside `minibrot_examples`; it came out right only because both commit by explicit path). **★ A DATA FILE THAT WOULD EXCEED `test_history_purity`'s 1 MiB is a HOT-TIER ARTIFACT plus a tracked rebuild command, never an allowlist entry.** **★ A LONG PROMPT RUNS IN ORDERED PHASES WITH A COMMIT PER PHASE.** **★ MEASURED (ckpt 109): `fractal-website`'s `builder check` holds the wallpapers `rows.jsonl` open and took three merges down with `WinError 5`** — the upsert lands anyway and retrying is the fix, but `merges.json`'s `new_recipes` under-reports for that leg afterwards. Treat a website check as a pool-adjacent job: never beside a wallpapers merge.

**★ RUN DURATION (Matt).** "An N-hour leg" = N hours of that producing leg alone; build, merge, readout, report outside it; no default overhead reserve. "Finish by X" = the envelope including setup and readout — reserve what those need, state it, size the leg to land on X. Ask when ambiguous. **★ AND A "FINISH BY X" PROMPT STATES THE GOAL AS AUTHORITY (2026-09-13).** When the planned route runs out, CC is explicitly authorized to advance the stated goal by other means and to say what it chose. **Idling to the wall, or re-running an exhausted leg, is a failure**. Naming only the fallback branches Claude happened to foresee is NOT enough. **A hunt cannot resume by rank — a budget-cut hunt is a seeded SAMPLE of its manifest; resumption is re-derivation** (2026-09-21). **An arm that needs a HARVEST before it can open anything (the plane sampler, ~6.2 s an openable place) cannot share a short producing window evenly with a hunt** — price the harvest first or give the arm the whole window. **A prompt that reads its size from the launch message also states the default CC takes when none arrives** (a leg once ran at CC's guess). **The budget is a target, not a cap.** **★ A LONG RUN CARRIES A 15-MINUTE HEARTBEAT (Matt, 2026-09-14)** — progress and a wall-clock timestamp, with the session still driving the box. ⚠ **A heartbeat detects nothing on its own** — arm a completion waiter in the same breath as every backgrounded launch and drive the units from one sequential driver. **★ WAIT ON THE REAL PROCESS, NEVER ON A LAUNCHER WRAPPER'S EXIT CODE** — the wrapper exits first. Matt's ruling: keep the night inside the conversational loop rather than detaching it to a script — a detached runner trades a loud failure for quiet ones. One run per budget; any follow-up is a new budget question. **Exploratory ~8 h runs: one prompt covers launch and postmortem** (not ~100 h runs). Long steps: estimate, background, cap at the finest safe interruption point, never start a unit that can't finish in budget. **★ A GUARD MAY BE WEAKENED OR DELETED FOR SPEED WHEN THE TRADE IS NAMED AND PRICED (Matt, 2026-09-15)** — this replaced "a slow guard moves lanes and is never weakened": say what stops being covered, put seconds beside it, take the pure wins first, and prefer thinning a claim to dropping one. The contract lives in wallpapers `CLAUDE.md`. **Before an overnight or any two-job night: reboot the box if its uptime is past a week** — the commit-charge leak and its failure signature are in wallpapers `tests/README.md §A lane sharing the box with a render leg`. Never run a test lane beside a leg on it.

**Mining-leg prompt rules** (PRE solves, naming a leg by its verb, no rate numbers, a prompt's shape vs the verb's reach) → `preserve\mining_laws.md`; read it before any mining prompt.

**★ FIGURE RECIPES ARE NEVER LOST (Matt, 2026-09-21).** Every website figure's render recipe lives site-side, tracked in git (a recipe is a few hundred bytes); a figure never depends on a wallpapers solve record existing, so solve records may be deleted freely. **★ "REMOVE THE SAVES" MEANS THE SAVES, NOT THE RECIPES** — ckpt 139 deleted 529 solve directories with their recipe files on that misreading and recovered the figures only from git history and ledger rows. **★ BACKUPS ARE MATT'S (2026-09-23).** A portable instance (`storage export`) is taken ONLY at his direction and never proposed because something new exists; he backs it up off-box and deletes the local copy at once, so nothing names or expects an instance on disk. Never a commit before he says "truly finalized". **★ `git grep <stamp>` BEFORE CALLING ANY RECORD STRAY** — a leftover once turned out to be `portable.REFERENCE`, named in tracked source.

**Before measuring, state which decision the number will change** — an experiment whose every outcome leads to the same action is not one.

**Audit-first:** when the session lacks the technical knowledge, STOP and ask Matt whether to send a facts-only audit prompt; never scaffold load-bearing content around CC-fill spots (exception: a placement-time verification list at the foot of a draft, corrected from source by CC). **Name the production entry point before auditing it** — from the records, not the docs. **Replay-first:** replay the last pass under any new selection rule before building. **Build ≠ flip:** staged in one prompt, adopted in another against a pre-registered bar. Non-negotiables: pre-registered eval bars · blind human reads of any model-selected population · reject autopsy (numbers AND a visual sample of admissions + rejects, drawn BEFORE any merge) · identity round-trips. **A fix with a shape needs the prompt, not a "yes."** **Queue order comes from dependencies** — what X needs and what needs X. **A policy flip asks who else applies the decision** — grep for private copies.

Fractal conventions: no tappable multiple-choice; correction sheets pre-labeled, sorted good→bad; `P(≥4) ≥ 0.5` is a trusted quality gate — never route seat-quality eye-checks to Matt; acceptance by eye except classifier evals.

## READING A REPORT

**Do not summarize it back** — say what it CHANGES, what Claude got WRONG, what's next, plus a "carry:" delta for the docs; trivial outcomes ≤2 sentences. What Claude got wrong is said in the chat, never carried in state; a mistake that REPEATS becomes one line in this doc. **CC's spec-deviations with stated reasons are consistently right — read before overriding.** A report opening with premises that did not survive is the normal case: carry the corrected figure, never the prompt's. Check supply claims, don't transcribe them. No "unreviewed by Matt" tracking; flag only what BLOCKS upcoming work. **A micro-task (a one-line text fix or trivial edit) is assumed handled once its prompt is delivered (Matt, ckpt 155)** — no report is awaited, tracked or listed as open. The site is draft — argue toward the final product, never from churn. **Figures are Matt's (ckpt 109)** — he checks every figure himself; never carry "which figures look wrong" as an open, and never spend a prompt confirming one. **★ Never propose re-picking or redrawing a figure because it drifted from the current records** (a dead source stamp, an old pass, a caption's literal claim): a caption gets at most a word fix (Matt, ckpt 152, after reverting an audit's re-picks item by item).

**Confidence convention:** every verdict carries basis (`[human n=X]` · `[machine-decode]` · `[measured]` · `[inferred]` · `[by-eye]`), population, overturned-by. No falsifier = a belief; `[machine-decode]` is evidence about the model, not the world. Cuts and floors are relative to a reference; every anchored precision is a ceiling. Never pool across an estimand change; a defaulted seed is a band. A "byte-identical" claim is proven by running the real commands, scoped to the module compared. **Verify from code, never from a sibling surface**; a library fact is not a pipeline fact; a feasibility verdict answers one parameterization. **A concurrency ratio is not a speedup** — candidates per wall second against a bit-exact serial arm is the only figure; the clock starts at the first unit of work. **A bulk approval is one mark, not N.** **A citation grep misses attribution by description**, and a `reports\` citation can sit in a tracked repo file the closeout seam never reaches.

Judge-method, split and labeling rules → fractal-corpus.

## EXCHANGE FOLDER & DRIVE

**★ DELIVERY SIZE RULE (2026-09-23).** The Drive tool takes a file's content inside the call, so every upload is re-emitted by the claude.ai session character by character. Therefore: text only, never base64; only short prompts (a few KB) go to Drive `prompts\`; any large body — a wholesale `fractal-state.md`, a prose master, a `preserve\` extract — is PRESENTED for Matt to place by hand: a handoff doc directly over its file in the controller folder, anything else at its stated destination. The apply prompt verifies it there (STOP if absent). **★ When it is unclear whether a Claude-side write will work, Matt places the file himself (Matt, ckpt 143)**, and every presented file comes with its exact destination path and file name. The session never re-reads into context a file it wrote in the same session, and never retries a failed upload with the same payload shape.

`C:\Code\fractal-drive-sync\{prompts,reports,prose,preserve,votes}\` — Drive-synced, outside all repos. **`votes\` is durable and append-only** (friends' picks; never wiped, never in a repo). **`preserve\` is durable**: cite by path; a file leaves only on Matt's ruling, recorded on the absorbing entry; keep `preserve\INDEX.md` (one line per file) current. Everything else is scratch. `matt-claude-workflow.md` at the root = the pattern for a new project.

**Resolve by PARENT CHAIN every session:** `fractal-drive-sync` by title + folder mimeType, then the subfolder whose parentId equals that id — never by title alone, sibling-filename check, or a parentId from a file search (another project has a same-named `prompts`). **`read_file_content` for all text fetches**; `download_file_content` is base64, binary only. **★ AN EMPTY `read_file_content` ON A JUST-WRITTEN REPORT IS DRIVE INDEX LAG, NOT AN EMPTY FILE (ckpt 135 — a 5 KB report fetched as base64 and then decoded cost ~10k tokens; the same read succeeded twenty minutes later):** confirm a non-zero `fileSize` in the search result, retry the read once, and if it is still empty ask Matt to upload or paste the report. NEVER fall back to `download_file_content` for text, and never paste base64 into a tool call to decode it. Drive files cannot be edited in place. Drive Desktop can lag `reports\` by hours — compare a report's fileSize to the last read before calling it unchanged; read from Matt's upload when Drive is stale.

**Edits split by size (Matt).** WHOLESALE replacement: claude.ai does it — **trash the old first, verify it is gone, then create** (creating first leaves a same-named pair Drive Desktop renames). A superseded prose master is TRASHED, never moved aside (Matt wiped `prose\old\` at ckpt 106; the folder still exists and is empty, and Drive version history is the recovery). SMALL edit: a trivial CC prompt editing the local synced file in place, targeted at `fractal-website`. Claude authors every word either way.

**★ WINDOWS BOX (ckpt 105).** Index-LF / worktree-CRLF drift is INVISIBLE to `git status` and `git diff` and rewrites every line the first time a `newline="\n"` writer touches the file; **`git ls-files --eol` is the ONLY detector**, and a repo needs `* text=auto eol=lf` for the CRLF→LF hook to protect it at all. The shell-edit preference, the hook's condition and the silent traps: `preserve\line_ending_playbook.md`.

**`reports\` and `prompts\` are wiped at every checkpoint boundary; Matt wipes `prompts\` himself.** `prompts\` and the exchange root are read-only to CC; an apply prompt may wipe `reports\` only. One writer per subfolder; `scratch/` stays a report's canonical home.

## CLOSEOUT

The closing act is the CHECKPOINT CLOSEOUT ("distill" is banned). `CLOSEOUT_ckptXX_apply.md` = the controller-CC apply prompt (guard: six `fractal-*.md` at root, no Cargo.toml/src/tools — else STOP); **Continuation hand-offs are BANNED (Matt, ckpt 106 — they caused serious problems): finish the active prompts, then a full closeout.** Exactly ONE hand-off artifact per checkpoint — a fresh session's context is written INTO state, never a side file. Queued-but-not-started prompts may stay in Drive `prompts\` across a closeout for the next instance; state names them QUEUED and the keep list excludes them from the wipe. **"PREPARE FOR CLOSEOUT" (Matt, ckpt 106)** = walk the conversation so far; accumulate questions for Matt; list every prompt still expecting a report; if useful, gather the remaining issues into one final pre-closeout prompt for wallpapers/website — especially README promotions, extractions to `preserve\` and superseded lines, so the handoff docs shrink. **Every pending edit Matt has parked (a sentence, a caption, a trivial task) rides the VERY NEXT prompt to that repo, never held back for the pre-closeout prompt or given a prompt of its own** (ckpt 153 and 154: one sentence was held back twice).

- **Only from a settled state** — never mid-session or before the era's final report; with a prompt outstanding only when Matt says so, then state names it IN FLIGHT. Corrections to a handed-off closeout prompt are addendum files.
- **Selective:** emit only the docs the era touched or invalidated, plus state; an untouched doc cannot grow. Walk the manifest once — TOUCHED / INVALIDATED (truth changed without an edit — flag in state, never silence) / CLEAN.
- **The session AUTHORS all content; the apply prompt is mechanical** — exact hunks (verbatim unique match or STOP), never composing or condensing. Wholesale whenever cheaper; **state is always wholesale and holds no facts** (status/plan/flags/roster). **Wholesale files travel as presented files Matt places himself, DIRECTLY over the doc they replace in the controller folder (Matt, ckpt 145)** — never as a sibling in `prompts\`, never inside the prompt or via Drive (newly authored text only: a VERBATIM move of existing doc text into `preserve\` is a script step, anchored by heading or opening phrase); the prompt verifies each in place: it differs from HEAD, and its first line names the new checkpoint, untouched files untouched, single-home spot-grep, size sanity. A closeout may split into numbered apply files, each committing.
- **Hunk rules:** no OLD text overlaps text an earlier step of the same file deletes or moves; edits to moved content target the destination; MOVE steps sort last.
- **Citations:** every `reports\`/`prompts\` citation is DROPPED, EXTRACTED (into a doc or `preserve\`, pointer follows) or KEPT (open item; report on state's keep list); the apply prompt greps survivors against the list.
- State the scratch-preservation notice (default nothing). Grep each bolded numeral across emitted docs; assert single occurrence.
- ⚠ **`preserve\` is NOT in the controller folder.** The controller holds `CLAUDE.md`, `.gitattributes`, `.gitignore` and the six `fractal-*.md` docs, and nothing else. `preserve\` is `C:\Code\fractal-drive-sync\preserve\`, which is where `parked.md`, the `rulings_*.md` set, `retention_design.md`, `solver_design.md` and `leveled_identity.md` live. A closeout script that says otherwise is wrong about the layout, not describing a move.
- ⚠ **A closeout DOES commit.** The controller folder is a git repo and `CLAUDE.md` asks for a clean working tree before applying, so the closeout ends with one commit whose message is `ckpt N`. Leaving the applied docs uncommitted breaks the next prompt's precondition.
