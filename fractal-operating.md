# fractal-operating — the method

Rewritten in full at ckpt 101 (earlier: 50, 65, 71, 77, 82, 91). Editable at any closeout, with care — this doc is the infrastructure everything else runs on: every edit is a deliberate hunk, and a rewrite is a stated act listed here. Read first, every session. Ownership test for every line: *would this still be true if the project weren't fractals?* If not, it belongs in another doc or a repo README. Organized by WHEN a rule fires. ★ = must not skim; bold = the load-bearing clause.

## ALWAYS

**Readers and homes.** Claude writes the six docs for a future fresh Claude. CC reads each repo's `CLAUDE.md` + READMEs + what a prompt cites; claude.ai reads the six docs + `preserve\` on demand; Matt reads none routinely. A repo mechanic lives in that repo's README/CLAUDE.md; the docs point (`→ module/README.md §…`) only where the README actually owns it; specs for unbuilt work live in `preserve\`; the docs keep only what changes a future session's decision. Roster: operating (method) · state (plan/status/flags/roster, every closeout) · tutorial (wallpapers repo + website) · corpus (labels, sampling, judge method) · discovery (sourcing truths) · engine (cross-repo render truths). Retired docs → controller git history.

**★ NEVER ENTER THE CODE REPO (Matt).** Docs live in `C:\Code\fractal-maker-controller`, changed ONLY by an applier CC through an apply prompt. Matt never edits them — any doc-vs-memory discrepancy is Claude's error. **A listed upload may not be rendered into context — `cat` it before answering from it.**

**★ THE DELETION TEST (Matt).** *The docs are the active wavefront, not a history.* A line survives only if it would change a FUTURE decision and cannot be encoded in code: decisions not yet made · caveats that would make a result be MISREAD · true-but-unenforceable facts. A number in a tracked repo file never appears here (verdict + path) · a guarded fact = one line + `[code: path]`, the guard is the memory · a closed arc ≤3 lines · run facts live in run records · a never-re-raise ruling → `settled_rulings.md`. No size targets — the deletion test and the guard inventory are the controls. A queue line naming no record in any repo is a dangling reference, not a task. The failure mode is Claude's: carrying a CC report instead of cutting the line it closes.

**Single-home and tagging.** One home per fact; other docs point. A line asserting what the tree does carries `[code: path]` or `[unverified]`; a claim of automatic future behaviour names its mechanism or is not written. **The guard inventory is a repeatable pass** (verdict every claim ENFORCED / OWNED / ORPHAN / STALE / BELIEF; promote orphans to their README first, then cut enforced and owned ones to a pointer) — run it whenever the docs feel heavy, as a read-only CC audit that runs beside other work. The 2026-09-05 pass read 452 claims, 72% already owned; its miss was a line whose home had landed the day before, and its one wrong STALE came from comparing two populations — verify a STALE against the stated population before acting on it. **★ A DATED ORPHAN VERDICT GOES STALE IN HOURS (ckpt 113)** — two of four claims a same-day audit called unowned were already owned at HEAD when the promotion prompt ran, so verify an ORPHAN from source at the moment of promoting, never from the audit. **★ A READER SWEEP IS ONLY AS GOOD AS ITS DATE (ckpt 111)** — a "nothing reads this" claim dated 2026-08-30 was three days older than the reader that had appeared, an audit repeated it, and it became a prompt to delete 7 GiB. Prose that was true when written is the most dangerous kind. The verify-from-source line in the destructive prompt is the only reason nothing was lost, so never drop it.

**Grep the `preserve\rulings_*.md` parts when it makes sense to, erring toward SKIPPING (Matt, ckpt 113)** — the store is six subject files (corpus · curation · sourcing · engine · website · method) with a stub index at the old path; re-entry is a question to Matt from a demonstrated repo need. Unscheduled → `preserve\parked.md`.

**Standing positions (Matt):**
- **★ RUNS ARE PRODUCT; LABELING IS AN EVAL ACTIVITY.** No verification homework on a run; no labels in the loop of a long run; a run whose allocation depends on fresh labels is refused. Retrain when a decision needs it, never preemptively.
- **Clean repo:** everything pulls in context-free; labels flat; cleanliness over byte-identity; shipped weights trained in-repo. *"About fractals, not ML."*
- **No archaeology; deletion is normal; usefulness before recoverability** — delete the regeneration machinery with the data if nothing will want it back. Retention is Matt's, outside the repo.
- **Nothing load-bearing lives in `scratch/`, both ways** — evidence leaves it when it justifies a decision; a proposal computed there never leaves as a fact. Unenforced; Matt wipes scratch between checkpoints. **★ THE CODE THAT PRODUCED A COMMITTED ARTIFACT IS LOAD-BEARING EVEN THOUGH THE ARTIFACT IS COMMITTED (ckpt 110)** — a figure maker left in `scratch/` was wiped, and the next one-word correction to that picture cost an image-forensics reconstruction of its parameters. A maker moves out of `scratch/` when its output is committed. Repo-doc admission = something in the code owns it and it stays true as the code changes; a transient measurement's survivors are extracted and the source deleted.
- **Irreplaceable record first** — a durable record written after a fallible step is not durable. **Losing hand-labeled data is a major failure**: nothing rewrites, deletes or re-keys label rows; re-attribution is reader-side; verify exports by row count. A tracked record is never edited in place (exception: a split REGISTRATION is a pre-build declaration).
- **★ A TEST FIXTURE IS WRONG ABOUT WHAT IT ISOLATES UNTIL PROVEN.** Redirect at the tier roots, never by accessor, so record, tree and unlink move together; check each path against the roots at the point of deletion. **A prompt adding a destructive writer says its isolation must be proven before it runs once.** Three catches in one era (ckpt 105): three test files read the box's real supply sidecar for weeks (57 s of a 177 s lane, and a fresh clone would have failed); the plan guards seeded off `artifacts/` and passed on a clone for the opposite reason; an accessor-level redirect let an intermediate state overwrite two tracked manifests. Where no root exists, a session-level hash of every tracked manifest is the backstop.
- **★ THE 10,000-HOUR FRAME:** judge every product choice by *what makes the best-framed, highest-quality, most beautiful, most diverse collection given 10,000 hours*. Discard-and-never-revisit is bad; over-admit and let the embedding and the solve reject near-duplicates. Don't over-think small counts.
- **★ COMPUTE COST IS NOT AN ARGUMENT IN A PRODUCT DECISION (Matt, ckpt 109).** The goal is a strong, diverse gallery, and the time to reach it is irrelevant unless it runs to months, which nothing here does. Make the quality case on its own; a per-clear cost is a SIZING input, never a reason to demote, drop or keep anything. Claude conflated the two once and was corrected — the `curvature` standing rests on its pictures rarely being good, not on its price.
- **10,000-hour stress test on every durable record:** size scales with knowledge gained, never work done — multiply growth by 10,000 h ÷ hours run; if absurd, fix the design now. A file read in full carries a stated bound; retention that drops the picture drops the row; per-render facts go in counters or run records. A leg's own measurement record retires WHOLE, never pruned by row.
- **A rule's purpose bounds its scope** — name what it protects before refusing on it. **Two spellings of one fact is a silent null.** **A declared design the launch doesn't read is not the design** — guard two-ended; explain a surprise only after the realized recipe is verified.

**Context stewardship:** track the session; ~150k is the WARN point, said with the estimate; Matt decides when to close out.

## WRITING A PROMPT

**Delivery.** Every prompt is a short `.md`, presented AND delivered as a confirmed Drive create into `prompts\` in the same turn — presenting alone is not delivery. **A delivered prompt is never edited** — corrections are addendum files (`<prompt>_addendumN.md`, "paste with the original"). **★ A PROMPT NAME THAT COULD RECUR IN A CYCLE CARRIES `_ckptNN_`** — the date alone cannot separate two closeouts in one day, and `prompts\` has twice held two files of one name.

**Shape.** TARGET-REPO guard first (`fractal-wallpapers` / `fractal-website` / `fractal-maker` / `fractal-maker-controller`), STOP on mismatch; "Commit when done." last unless it says why not. Each repo's `CLAUDE.md` owns the standing contract (report path/shape/delivery, README promotion, concurrency, backgrounding, the commit gate) — never restated. Wallpapers' `CLAUDE.md` carries BOTH a backgrounding rule and a commit gate (verified 2026-09-05; these docs said otherwise for weeks and every prompt restated them). Length scales with risk; trust CC on mechanics. **State the goal; the anchor is a hint** — authorize CC to normalize whitespace, repair a near-miss anchor and resolve a contradiction between two of the prompt's own instructions, reporting what it chose; STOP only for a genuinely ambiguous target. Every append checks the fact isn't already there. Full paths in any delete/move; state the new names for what moves; instruct verify-from-source over these docs. Matt dictates config values; the prompt applies them. Never mention git push, remotes or commit state. **A prompt that stops a leg kills its OWN workers by pid, never every engine on the box** (a website rig killed a wallpapers pytest's engine next door, ckpt 106).

**★ AN UNATTENDED PROMPT NEVER CONTAINS A STOP-AND-ASK GATE (Matt).** The wrong-repo guard is the only STOP; every other gate is a branch — do what fits, record what didn't, continue — and the prompt says so up front. Stop time may arrive in the launch message. Exception: a closeout apply-script's STOP-on-failed-match. **An eye-check prompt never stops either** — it always delivers the sheet, taking the least-bad choice and saying so.

**★ ONE COMMIT AT A TIME PER REPO.** Repos run concurrently; two prompts in one repo only when one will not commit while the other might, never when both write a tracked file. **A prompt that runs BESIDE another in the same repo writes nothing tracked, holds no pool, and OMITS the commit line** — reports live in `scratch/` + Drive `reports\`, never in git, so the only collision is the `git commit` itself. **No second committing prompt starts while another has uncommitted changes; a clean `git status` that holds for a minute is not a handover.** A website prompt that may touch the engine locks BOTH repos; say so in the header. **★ MEASURED (ckpt 109): `fractal-website`'s `builder check` holds the wallpapers `rows.jsonl` open and took three merges down with `WinError 5`** — the upsert lands anyway and retrying is the fix, but `merges.json`'s `new_recipes` under-reports for that leg afterwards. Treat a website check as a pool-adjacent job: never beside a wallpapers merge.

**★ RUN DURATION (Matt).** "An N-hour leg" = N hours of that producing leg alone; build, merge, readout, report outside it; no default overhead reserve. "Finish by X" = the envelope including setup and readout — reserve what those need, state it, size the leg to land on X. Ask when ambiguous. **A prompt that reads its size from the launch message also states the default CC takes when none arrives** (a leg once ran at CC's guess). **The budget is a target, not a cap.** One run per budget; any follow-up is a new budget question. **Exploratory ~8 h runs: one prompt covers launch and postmortem** (not ~100 h runs). Long steps: estimate, background, cap at the finest safe interruption point, never start a unit that can't finish in budget. Slow test lane OFF unless Matt names it. **Before an overnight or any two-job night: reboot the box if its uptime is past a week** — the commit-charge leak and its failure signature are in wallpapers `tests/README.md §A lane sharing the box with a render leg`. Never run a test lane beside a leg on it.

**★ NEVER PUT A RATE NUMBER IN A PROMPT** — say "pilot it" and name the population; historical rates live in one table in `curation/README.md`. Budget a leg off an OBSERVED leg, never a rate; a price is the mean over the real population (name it, or say "unpriced"); pilot on the target population to a fraction of the leg's candidates (the fraction → wallpapers `LEGS.md §Pilot to a fraction of the leg`), never a fixed wall — a short pilot is a floor; a zero-yield batch prices itself; price a removed render/IO line against a cold cache.

**Before measuring, state which decision the number will change** — an experiment whose every outcome leads to the same action is not one.

**Audit-first:** when the session lacks the technical knowledge, STOP and ask Matt whether to send a facts-only audit prompt; never scaffold load-bearing content around CC-fill spots (exception: a placement-time verification list at the foot of a draft, corrected from source by CC). **Name the production entry point before auditing it** — from the records, not the docs. **Replay-first:** replay the last pass under any new selection rule before building. **Build ≠ flip:** staged in one prompt, adopted in another against a pre-registered bar. Non-negotiables: pre-registered eval bars · blind human reads of any model-selected population · reject autopsy (numbers AND a visual sample of admissions + rejects, drawn BEFORE any merge) · identity round-trips. **A fix with a shape needs the prompt, not a "yes."** **Queue order comes from dependencies** — what X needs and what needs X. **A policy flip asks who else applies the decision** — grep for private copies.

Fractal conventions: no tappable multiple-choice; correction sheets pre-labeled, sorted good→bad; `P(≥4) ≥ 0.5` is a trusted quality gate — never route seat-quality eye-checks to Matt; acceptance by eye except classifier evals.

## READING A REPORT

**Do not summarize it back** — say what it CHANGES, what Claude got WRONG, what's next, plus a "carry:" delta for the docs; trivial outcomes ≤2 sentences. **CC's spec-deviations with stated reasons are consistently right — read before overriding.** Check supply claims, don't transcribe them. No "unreviewed by Matt" tracking; flag only what BLOCKS upcoming work. The site is draft — argue toward the final product, never from churn. **Figures are Matt's (ckpt 109)** — he checks every figure himself; never carry "which figures look wrong" as an open, and never spend a prompt confirming one.

**Confidence convention:** every verdict carries basis (`[human n=X]` · `[machine-decode]` · `[measured]` · `[inferred]` · `[by-eye]`), population, overturned-by. No falsifier = a belief; `[machine-decode]` is evidence about the model, not the world. Cuts and floors are relative to a reference; every anchored precision is a ceiling. Never pool across an estimand change; a defaulted seed is a band. A "byte-identical" claim is proven by running the real commands, scoped to the module compared. **Verify from code, never from a sibling surface**; a library fact is not a pipeline fact; a feasibility verdict answers one parameterization. **A concurrency ratio is not a speedup** — candidates per wall second against a bit-exact serial arm is the only figure; the clock starts at the first unit of work. **A bulk approval is one mark, not N.** **A citation grep misses attribution by description**, and a `reports\` citation can sit in a tracked repo file the closeout seam never reaches.

Judge-method, split and labeling rules → fractal-corpus.

## EXCHANGE FOLDER & DRIVE

`C:\Code\fractal-drive-sync\{prompts,reports,prose,preserve}\` — Drive-synced, outside all repos. **`preserve\` is durable**: cite by path; a file leaves only on Matt's ruling, recorded on the absorbing entry; keep `preserve\INDEX.md` (one line per file) current. Everything else is scratch. `matt-claude-workflow.md` at the root = the pattern for a new project.

**Resolve by PARENT CHAIN every session:** `fractal-drive-sync` by title + folder mimeType, then the subfolder whose parentId equals that id — never by title alone, sibling-filename check, or a parentId from a file search (another project has a same-named `prompts`). **`read_file_content` for all text fetches**; `download_file_content` is base64, binary only. Drive files cannot be edited in place. Drive Desktop can lag `reports\` by hours — compare a report's fileSize to the last read before calling it unchanged; read from Matt's upload when Drive is stale.

**Edits split by size (Matt).** WHOLESALE replacement: claude.ai does it — **trash the old first, verify it is gone, then create** (creating first leaves a same-named pair Drive Desktop renames). A superseded prose master is TRASHED — there is no `prose\old\` (Matt wiped it, ckpt 106; Drive version history is the recovery). SMALL edit: a trivial CC prompt editing the local synced file in place, targeted at `fractal-website`. Claude authors every word either way.

**★ WINDOWS BOX (ckpt 105).** Index-LF / worktree-CRLF drift is INVISIBLE to `git status` and `git diff` and rewrites every line the first time a `newline="\n"` writer touches the file; **`git ls-files --eol` is the ONLY detector**, and a repo needs `* text=auto eol=lf` for the CRLF→LF hook to protect it at all. The shell-edit preference, the hook's condition and the silent traps: `preserve\line_ending_playbook.md`.

**`reports\` and `prompts\` are wiped at every checkpoint boundary; Matt wipes `prompts\` himself.** `prompts\` and the exchange root are read-only to CC; an apply prompt may wipe `reports\` only. One writer per subfolder; `scratch/` stays a report's canonical home.

## CLOSEOUT

The closing act is the CHECKPOINT CLOSEOUT ("distill" is banned). `CLOSEOUT_ckptXX_apply.md` = the controller-CC apply prompt (guard: six `fractal-*.md` at root, no Cargo.toml/src/tools — else STOP); **Continuation hand-offs are BANNED (Matt, ckpt 106 — they caused serious problems): finish the active prompts, then a full closeout.** Exactly ONE hand-off artifact per checkpoint — a fresh session's context is written INTO state, never a side file. Queued-but-not-started prompts may stay in Drive `prompts\` across a closeout for the next instance; state names them QUEUED and the keep list excludes them from the wipe. **"PREPARE FOR CLOSEOUT" (Matt, ckpt 106)** = walk the conversation so far; accumulate questions for Matt; list every prompt still expecting a report; if useful, gather the remaining issues into one final pre-closeout prompt for wallpapers/website — especially README promotions, extractions to `preserve\` and superseded lines, so the handoff docs shrink.

- **Only from a settled state** — never mid-session or before the era's final report; with a prompt outstanding only when Matt says so, then state names it IN FLIGHT. Corrections to a handed-off closeout prompt are addendum files.
- **Selective:** emit only the docs the era touched or invalidated, plus state; an untouched doc cannot grow. Walk the manifest once — TOUCHED / INVALIDATED (truth changed without an edit — flag in state, never silence) / CLEAN.
- **The session AUTHORS all content; the apply prompt is mechanical** — exact hunks (verbatim unique match or STOP), never composing or condensing. Wholesale whenever cheaper; **state is always wholesale and holds no facts** (status/plan/flags/roster). **Wholesale files travel as presented files Matt places himself** — never inside the prompt or via Drive; the prompt verifies each is present and differs from HEAD, untouched files untouched, single-home spot-grep, size sanity. A closeout may split into numbered apply files, each committing.
- **Hunk rules:** no OLD text overlaps text an earlier step of the same file deletes or moves; edits to moved content target the destination; MOVE steps sort last.
- **Citations:** every `reports\`/`prompts\` citation is DROPPED, EXTRACTED (into a doc or `preserve\`, pointer follows) or KEPT (open item; report on state's keep list); the apply prompt greps survivors against the list.
- State the scratch-preservation notice (default nothing). Grep each bolded numeral across emitted docs; assert single occurrence.
- ⚠ **`preserve\` is NOT in the controller folder.** The controller holds `CLAUDE.md`, `.gitattributes`, `.gitignore` and the six `fractal-*.md` docs, and nothing else. `preserve\` is `C:\Code\fractal-drive-sync\preserve\`, which is where `parked.md`, the `rulings_*.md` set, `retention_design.md`, `solver_design.md` and `leveled_identity.md` live. A closeout script that says otherwise is wrong about the layout, not describing a move.
- ⚠ **A closeout DOES commit.** The controller folder is a git repo and `CLAUDE.md` asks for a clean working tree before applying, so the closeout ends with one commit whose message is `ckpt N`. Leaving the applied docs uncommitted breaks the next prompt's precondition.
