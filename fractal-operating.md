- State the scratch-preservation notice at every closeout — what under `scratch/` MUST survive; default nothing.

- **Hunk rules:** no hunk's OLD text overlaps text a prior step of the same file deletes or moves; edits to moved content target the DESTINATION file; MOVE steps sort last within their file.

**★ SIZE TARGETS, NOT HARD CAPS (Matt).** Soft targets in state's roster; the deletion test is the real control; targets move only with Matt. **state holds NO FACTS** — status/plan/flags/roster only, and status lives in state ALONE.

**★ THE DELETION TEST (Matt, firm).** *"These docs are the ACTIVE WAVEFRONT, not a history."* A line survives only if it would change a FUTURE decision AND cannot be encoded in code. Passes: decisions not yet made · measurement-validity caveats that would cause a future result to be MISREAD · true-but-unenforceable facts. Compression: **a number that lives in a tracked repo file never appears here** (verdict + path) · a guarded `[code:]` fact = one line + pointer, the guard is the memory · a closed arc ≤3 lines (verdict · what changed · record path) · run facts live in run records · a never-re-raise ruling is a TOMBSTONE → `settled_rulings.md`. **★ AN OPEN QUEUE ITEM'S RECORD POINTER IS THE LAST THING TO DROP, NEVER THE FIRST** — a queue line naming no record is a dangling reference. **A DANGLING REFERENCE IS NOT A TASK** — a line that sounds like one but names nothing in any repo fails this test. **The failure mode is Claude's: treating a CC report as material to CARRY rather than evidence a line can be CUT.**

**★ SINGLE-HOME.** Grep each bolded numeral across emitted docs and assert single occurrence; other docs NAME a fact and cross-reference, never restate — preserve docs included. **★ TAG CLAIMS ABOUT CODE.** A line asserting what the tree does carries `[code: path]` or `[unverified]`; a claim of AUTOMATIC FUTURE BEHAVIOR names the enforcing mechanism or is not written. Every checkpoint that checked has falsified some untagged claim.

**Emphasis.** ONE star tier: `★` marks a line a future session must not skim past, bold marks the load-bearing clause inside it — inflate either and both stop meaning anything. Telegraphic; rewording ≠ compressing — delete whole blocks. fractal-wallpapers has NO repo practice docs by decision (Matt); conventions live in CLAUDE.md. **Carry this document forward, amended or preserved, never eroded.**

## STANDING POSITIONS (Matt, firm)

- **★ RUNS ARE PRODUCT; LABELING IS AN EVAL ACTIVITY.** Runs are on Matt's schedule with no verification homework. **A LONG RUN (100 h+) MUST NEVER REQUIRE LABELING IN THE LOOP**, and a run whose allocation depends on fresh human labels is refused. Labeling re-anchors the books when it happens; high-value sources ACCUMULATE (fractal-corpus). **Retrain when a decision needs it, NEVER preemptively.**
- **★ THE CLEAN-REPO MODEL.** Fresh repo = everything pulled in cleanly, CONTEXT-FREE; labels FLAT; NO byte-identity requirement — cleanliness over byte-identicalness; shipped weights trained WITHIN the repo. Editorial line: *"this is about fractals, not ML."*
- **★ NO ARCHAEOLOGY; DELETION IS NORMAL.** Don't resurrect artifacts that don't match how things work now; retention is Matt's, outside the repo. **★ USEFULNESS BEFORE RECOVERABILITY** — if nothing will want it back, delete the regeneration machinery with the data; regenerability is not per-file when builds are chained.
- **★ NOTHING LOAD-BEARING LIVES IN `scratch/`, both ways** — evidence leaves it when it justifies a decision; a proposal computed there never leaves as a fact. ⚠ **There is NO enforced allowlist** (checked in tree) — this is a discipline, not a guard, and these docs once asserted an enforcement that does not exist. Matt wipes scratch between checkpoints.
- **★ A DURABLE RECORD WRITTEN AFTER A FALLIBLE STEP IS NOT DURABLE** — irreplaceable record first. **★ LOSING HAND-LABELED DATA IS A MAJOR FAILURE** — nothing rewrites, deletes, or re-keys stored label rows; re-attribution is reader-side; verify exports BY ROW COUNT. **A tracked RECORD is never edited in place** — fix the reader's semantics, or add an amendment beside it. ONE exception: a split REGISTRATION is a pre-build DECLARATION, so a wrong one is corrected in place [code: registry.refuse_contradiction].
- **★ A TEST FIXTURE IS WRONG ABOUT WHAT IT ISOLATES UNTIL PROVEN** (three times in one era) — redirect EVERY path the writer under test touches, or the fast lane reaches real data; a fixture naming inputs that were never on disk leaves the rule it guards silently inert.
- **★ REPO-DOC ADMISSION:** something in the code owns it and it stays true as the code changes; a transient measurement lives in scratch — survivors extracted, source deleted. **An extraction that does not delete its source is the failure; a rule nothing enforces is not a rule — name the guard.**
- **★ THE 10,000-HOUR FRAME (Matt)** governs every product decision — *judge every choice by "what makes the best-framed, highest-quality, most beautiful, most diverse wallpaper collection given 10,000 hours"; anything that discards and never revisits is generally bad; err toward over-admitting whatever could possibly be good and let the embedding and the solve reject near-duplicates*; pacing-never-rejection → settled_rulings. Don't over-think trivially small counts.
- **★ A RULE'S PURPOSE BOUNDS ITS SCOPE.** Before refusing or redesigning on a rule, name what it protects; if that is not in play, the rule is not either.
- **★ TWO SPELLINGS OF ONE FACT IS A SILENT NULL.** One adapter, one key, the reader asserts the spelling it expects; a witness on the wrong axis understates a gap.
- **★ A DECLARED DESIGN THE LAUNCH DOESN'T READ IS NOT THE DESIGN** — guarded two-ended, and the guard is the memory (→ fractal-corpus §Judge method). Explain a surprising result only after the realized recipe is verified.

## REASONING & MEASUREMENT

**Confidence convention.** Every verdict carries **basis** (`[human n=X]`·`[machine-decode]`·`[measured]`·`[inferred]`·`[by-eye]`), **population**, **overturned-by**. No falsifier = a belief; `[machine-decode]` is evidence about the MODEL, not the world.
- **★ Cuts and floors are RELATIVE TO A REFERENCE, never absolutes.** Every precision in a lock or anchored rate is a CEILING.
- **★ NEVER POOL ACROSS AN ESTIMAND CHANGE. A REGENERATION MOVES EVERY MEASURED ROW** (partial adoption = hand-splice). **A DEFAULTED SEED IS A BAND**, not a neutral prior.
- **★ PRICING.** (1) **BUDGET A LEG OFF AN OBSERVED LEG, never off a rate** — rate extrapolations understate roughly twofold, worse for bulk small-file moves; stage anomalies rank by ratio to the unit's OWN median. (2) **A PROMPT'S PRICE IS THE MEAN OVER THE REAL POPULATION** — name the population and the statistic, or say "unpriced"; every partition's median is under half its mean, so a mean over a mode draw is a mean over a bimodal population. (3) **COST TRACKS WHAT THE PIXELS DO** — pilot on the target population before sizing any leg; a prior from another population has been wrong by an order of magnitude. **★ ⚠ A SHORT PILOT IS A FLOOR, NOT AN ESTIMATE — PILOT TO A FIXED FRACTION OF THE LEG (~20% of its candidates), NEVER A FIXED WALL:** a three-minute pilot cannot reach a population's expensive tail and has under-priced a partition by two thirds, while a pilot sized at a fifth of its leg priced to a fraction of a percent. Price a REMOVED render/IO line against a COLD cache. (4) **MAXITER DOES NOT PRICE A PARTITION, AND THE MODE PRICES A CANDIDATE AT LEAST AS HARD** — composites are the majority of the bill on a minority of candidates, and one mode can cost several times another inside one partition; **size a budget on candidates × partition rate × mode-kind rate.** (5) ⚠ **`time.monotonic` HAS A 15.6 ms FLOOR ON WINDOWS** — any recolour-scale profile taken on it is void. (6) **A FILENAME THAT ENCODES A SPLIT IS NOT AN IDENTITY** — a chunked resume must subtract MEASURED identities (a sweep once skipped 42% of its pairs per location while reporting success), and composites scale superlinearly in maxiter. (7) **⚠ A CONCURRENCY RATIO IS NOT A SPEEDUP** — engine-seconds over wall over-reads the delivered speedup by most of a factor, and a run record's own `concurrency` field over-reads too; the delivered figure is measured against a BIT-EXACT SERIAL REPLICATION, an engine sharing the machine costs more per candidate, and that inflation counts as work. **Candidates per WALL second against a serial arm is the only figure that means anything.** **A budget clock starts at the first unit of WORK**, never at launch.
- **★ A "BYTE-IDENTICAL" CLAIM IS PROVEN BY RUNNING THE REAL COMMANDS** — and scoped to the module compared. Test-construction and bar-vs-instrument rules → fractal-corpus §Judge method.
- **★ VERIFY FROM CODE, NEVER FROM A SIBLING SURFACE** — docs ↔ site ↔ code consistency is proven from code; a LIBRARY fact is not a PIPELINE fact; a feasibility verdict answers ONE parameterization. **★ NAME THE ENTRY POINT THAT IS ACTUALLY IN PRODUCTION BEFORE AUDITING IT** — two audits in one era each had to correct the command the docs named before they could answer anything, and the docs had described a loop carrying under 1% of the work for two eras. Confirm from the records which code path made the rows, not from what the docs call it.
- Judge-method and split rules are OWNED by fractal-corpus — point, don't restate.

## WORKING STYLE

**One CC prompt at a time PER REPO** — different repos concurrent by default; same-repo parallelism only when verified (overnight wait-gate queueing; a second CC beside a GPU-bound wait; read-only audits beside anything). **⚠ SAME-REPO CONCURRENCY IS NOT FREE EVEN UNDER EXPLICIT-PATH COMMITS** — a beside-running prompt's commit swept up the other's README additions despite the instruction; assume a shared commit, and never pair two prompts where either writes a tracked file the other touches. **★ A website prompt that may touch the engine LOCKS BOTH repos (Matt)** — check in-flight state across both and say so in the header. Progress-through-delivery over method minutiae; scope narrow; **diagnosis-first is NOT a standing policy.**

**★ RUN DURATION (Matt; the old N−2 reserve is DELETED — never apply a default overhead reserve).** "An N-hour MINE or CRAWL" — any producing leg — means **N hours of THAT LEG**; build, merge, readout and report sit OUTSIDE the number, unless Matt clarifies for that prompt. **"Finish by X"** names the ENVELOPE and includes setup and readout: reserve the build and report actually expected, STATE the reservation in the prompt so Matt can correct it, and size the leg to land on the deadline. Ask when a case is ambiguous. **The budget is a TARGET, not a cap** — stopping early is wasted time, not a success. **One run per budget — a follow-up of ANY length is a NEW budget question.** **★ EXPLORATORY ~8 h RUNS: ONE PROMPT COVERS LAUNCH AND POSTMORTEM** — CC stays up across the run and writes the readout; separate readout prompts only as follow-ups; not for ~100 h runs.

- Prompts = short `.md`, presented AND delivered; length scales with risk; trust CC on mechanics. **★ CC's honest spec-deviations with stated reasons are consistently right — read before overriding.** Supply claims to be CHECKED, not transcribed.
- **★ A MECHANICAL-EDIT PROMPT STATES THE GOAL; THE ANCHOR IS A HINT, NOT A CONTRACT (learned the hard way, ckpt 91 — four round trips, every failure Claude's).** The pattern was over-specifying the mechanism while under-specifying the intent: a uniqueness guard the very paragraph being deleted made unsatisfiable · one step ordering two citations repointed while another said to keep history, where one of them WAS history · an exact hunk that missed only because the file hard-wraps. Each time CC could see the right answer and the prompt had left it no room to act, and **the one clean outcome came from CC ignoring the literal rule and matching across the wrap.** So: say what an edit is FOR, give the anchor as the best-known text, and **authorize CC to normalize whitespace and wrapping, repair a near-miss anchor, and resolve a contradiction between two of the prompt's own instructions** — reporting exactly what it matched and what it chose. Reserve STOP for a genuinely ambiguous target or contested content. **And EVERY append checks whether the fact is already there** — the one step carrying that check caught a duplicate; the one without it made one. **★ ⚠ NEVER PUT A RATE NUMBER IN A PROMPT** — session-carried rates were wrong four times in one era, once by more than an order of magnitude, every time by quoting a figure measured under other conditions as though it priced the new leg. A prompt says "pilot it" and names the population, never a number; historical rates with their conditions live in ONE table in `curation/README.md`.
- **★ AFTER A REPORT, DO NOT SUMMARIZE IT BACK** — say what it CHANGES, what Claude got WRONG, what's next, plus a short "carry:" delta of what the docs must change; trivial outcomes ≤2 sentences (Matt). **★ NO "UNREVIEWED BY MATT" TRACKING** — assume CC's calls and the rendered state are fine until Matt says otherwise; flag only decisions that BLOCK upcoming work. The site is DRAFT — argue toward the right FINAL PRODUCT, never from churn.
- **★ NEVER EDIT A PROMPT ALREADY HANDED OVER** — addendums. Matt does NOT hand-edit JSON/config — he dictates, the prompt applies. Acceptance BY EYE except classifier evals. Git — commits, push, remotes — is his entirely; never flag or mention its state.
- **★ A FIX WITH A SHAPE NEEDS THE PROMPT, NOT A "YES."** **★ AUDIT-FIRST:** when a task needs technical knowledge the session lacks, STOP and ask Matt whether to send a facts-only audit prompt — never scaffold load-bearing content around CC-fill spots (accepted exception: a placement-time verification list at the foot of a draft, which CC corrects from source and reports); audits report facts, the session authors prose. **★ REPLAY FIRST:** for any selection rule, replay the last pass under it before building (a read-only replay once found four shape errors in a Matt-ratified design). **★ AN EYE-CHECK PROMPT NEVER STOPS (Matt):** it always delivers the sheet; on a failed derivation it takes the least-bad choice, says so, and still renders — "I can't do anything from text." **★ A BULK APPROVAL IS NOT PAIR VERDICTS:** a block approval is one mark, not N; derive constants only from marks Matt actually made, and put the pairs the derivation turns on in front of his eye. **★ A POLICY FLIP ASKS "WHO ELSE APPLIES THIS DECISION?"** — grep for private copies. **★ BUILD ≠ FLIP** — staged in one prompt, adopted in another against a pre-registered bar. Non-negotiables bought by disasters: pre-registered eval bars · blind human reads of any model-selected population · reject autopsy + identity round-trips. **Reject autopsy — standing habit:** every readout emits numbers AND a visual sample of admissions + rejects.
- **★ Name full paths in any delete/move instruction** — "delete v7" is a version, not a path. **★ QUEUE ORDER COMES FROM DEPENDENCIES, NEVER FROM WHAT IS ALREADY RULED (Matt):** ask what X needs and what needs X — a build whose benefit lands later still costs nothing to build now.
