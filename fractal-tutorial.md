## The mining loop
Plan shape, arms, retention, conditioning, every flag and rate → `LEGS.md` / `MEASUREMENTS.md`. Decisions and traps:
- **★ THE MINABLE POPULATION IS THE LEDGER'S RATINGS, NOT A SCAN.** An empty partition appears as a zero.
- **★ THE PRODUCTION MINING LOOP IS `curate depth run`** — plan fixed before the first render, no stage reads a score. **Partition share is `curation/draw_weights.py`** (`SECONDS_SHARE` for the phoenix planes). **Breadth has no per-mode weight.** `--draw-cells` is an n≤1000 COMPOSITION instrument (ruled). ⚠ `depth`'s NEUTRAL roster is field modes — name `--modes` for the dear kinds. ⚠ `--floor-seats` defaults to 10 and plans nothing at that default. ⚠ **The angle modes are not `colorize.shareable`** — every candidate is a full render; size an angle leg off `night_c` (`MEASUREMENTS.md`), not off a mixed-roster price. **★ THE NEAR BAND NEVER CHOOSES A MODE (ckpt 114)** — `plan_held_mode` renders `best_mode`, and `best_field_by_location` takes the highest-scoring ledger row at the place whose mode is anywhere in the roster, so **widening `--modes` prices the band by changing which incumbent wins the argmax** rather than by adding modes to try. `--breadth-demoted` narrows breadth independently; the inverse, a band narrower than breadth, is NOT expressible. ⚠ **Judge a band arm on SEATS, never on kept clears** — the two halves differ 4.8–6.7× in price and only 1.3–1.6× in conversion, and they are level on seats. Decomposition and prices → `curation/LEGS.md`.
- **★ RETENTION DROPS ROWS AND THEIR PICTURES TOGETHER, INSIDE `merge`.** `merge` upserts, incoming WINS — **incumbents may be displaced by better rows; no protecting knob (ruled ckpt 108).** ⚠ There is NO incoming-wins: `retention.decide` is a pure function of the rows standing after the upsert, sorting `(-rank value, recipe key)` and keeping the first K, so an incumbent and an arrival are ranked on identical terms. The key is `(location.key, colorize.spelled(mode, mode_params))` and colour is in the RANKING, never the grouping. **★ `RETAIN_PER_PAIR` IS 5 (built ckpt 112) and `retention.free_slots` / `curate candidate-ledger free-slots` compute a free slot as `K − len(pair)`. ⚠ AT K=5 THE MANIFEST NARROWS NOTHING; what bounds a near-band arm is the BAND, not the manifest. ⚠ The "a pair under the keep has never had more attempts" reading now holds only BELOW 3 — most pairs sitting at exactly 3 were pruned at the OLD keep, so their slots are room and not evidence anybody has looked (counts → `preserve\retention_design.md`). ★ THE PRUNE'S BINDING SURFACE IS THE PAIRS OVER K, AND IT IS TINY — 106 of 119,231 pairs today, so a pool-wide rank-change count overstates a merge's effect by three orders of magnitude (Matt, ckpt 111)** — 3 is a floor, not slack, and the colour key is closed against; evidence → `preserve\retention_design.md`. **★ A PAIR UNDER THE KEEP HAS NEVER HAD MORE ATTEMPTS** (prune keeps `min(K, attempts)`), so a free slot is `K − len(pair)` and needs no scan — the rule that would have caught `thin2_b_near`. Merge between legs, never after both. ⚠ **A near band over a prune-free opener is EMPTY** — size the opener with room under `RETAIN_PER_PAIR` (`LEGS.md §--near-places`, measured: one row per free slot, the rest is quality). The point draw is SEEDED.

## Caveats that would cause a misread
- **No head ever scores the wallpaper that ships** — judges read the 640×360 candidate; a release row is a COLD render with autolevel INSIDE it. ⚠ A depth row's stored picture is the LEVELLED picture the judge scored (→ fractal-engine). ⚠ **A reader that takes a seat's mode off `gallery.jsonl` gets the ROUTED mode — render at `recipe["mode"]`.** ⚠ **The rank key reads `flatness`, so every seating is BUSIER than the pool by construction** — intentional (Matt, ckpt 107; figures → `MEASUREMENTS.md`).
- Every location in a run is attempted 1 smooth + 2 strange; pools DISJOINT per KIND; **under-fill is the strange bar.**
- ⚠ A RESUME REPLACES the CURATION run record WHOLESALE; harvest `--minutes` = ACTIVE time; check the pool size on the record before trusting last week's figure.
- **★ LIBRARY ≠ DRAWABLE** — palettes → `palettes/README.md`; **never merge a pair marked DIFFERENT**; the palette head PICKS in the production loop; `blue_orange`: Matt's eye is calibrated on the FOLDED ramp. 1,021 maps / 942 drawable since the `classic-pairs-2026-09` drop (ckpt 109: 120 cyclic maps, zero name collisions, and no existing map's bake moved). `palette_sets.admit()` / `fractal-wallpapers palette admit` is the clone-runnable writer for the drawable pool. **★ THE MINING DRAW NEVER TOUCHES THE PALETTE HEAD** — `colorize.pool(seed)` plus a seeded RNG in the leg planner; the head appears only at `Colorizer.pick_palette` on the `curate run` release path and takes a PICTURE, not a colormap, so a new map needs no head work at all.
- **★ `scores_by_recipe` RAISES ON A MIXED REGIME WHEN NONE IS NAMED (ckpt 111)** [`store.LedgerError`; ~0.04 s on the largest read in the tree]. `regime` is KEYED on `Recipe` and all six score writers stamp it, so `recipe_key → regime` is a function today and the collision is unreachable by drift — it becomes reachable through exactly one door, re-scoring at shipping geometry. Six callers still pass `regime=None` and naming one at each is the precondition for any second regime; `remode` is routed through the guarded function, and ⚠ `rerender.rescore`'s `held` set is regime-blind, so under two regimes it would count a recipe read at the other geometry as already scored. ⚠ `renders.job_name` digests the CHECKOUT path (→ fractal-engine). ⚠ **BOX MEMORY IS COMMIT CHARGE AND LEAKS** (`tests/README.md §A lane sharing the box with a render leg`) — the one-pool-per-box rule reaches across repos; a lane runs AFTER a pool-holding leg, never beside (a streaming leg such as a votes build is not one). **A prompt that stops a leg kills its OWN workers by pid, never every `fractal-engine.exe` on the box.**
